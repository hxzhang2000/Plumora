## 一、产品概述

### 1.1 产品定位

观梅 · Plumora 是一款**梅花易数起卦与排盘工具**，帮助用户随时随地以传统梅花易数方法起卦、排盘、查阅卦象知识，并保存卦例以便复盘验证。产品定位为「**传统文化学习工具**」，而非算命服务。

### 1.2 目标用户

| 用户群 | 特征 | 核心诉求 |
| --- | --- | --- |
| 梅花易数学习者 | 入门到进阶，正在学习《梅花易数》原著 | 快速准确起卦排盘，对照学习体用生克与类象 |
| 国学/易经爱好者 | 对卦象感兴趣，非专业 | 低门槛体验起卦流程，查阅卦辞爻辞 |
| 传统命理从业者 | 有手动排盘经验 | 移动端快速排盘 + 卦例存档管理 |

### 1.3 核心价值

1. **准确**：起卦算法严格遵循梅花易数传统规则（先天八卦数、取余规则、余零取 8/6）。
2. **全面**：一次起卦同时给出本卦、互卦、变卦、动爻、体用、五行生克结论。
3. **可留存**：卦例本地存档，支持备注与应验标记，便于复盘学习。
4. **离线可用**：全部功能离线运行，数据不出设备。

### 1.4 名词术语

见 `docs/dev/README.md` 第三节「术语速查」。

### 2.2 功能需求详述

#### FR-01 时间起卦（P0）

| 项目 | 说明 |
| --- | --- |
| 描述 | 以起卦时刻的农历年（地支序数）、农历月、农历日、时辰序数为参数起卦 |
| 输入 | 默认取当前时刻；时间来源分段控件可切换为「公历 / 农历」手动输入（年份 1900–2100、时 0–23，农历含闰月开关；口径见 03 文档 §6.4） |
| 计算规则 | 上卦 = (年支序数 + 农历月 + 农历日) mod 8，余 0 取 8；下卦 = (年支序数 + 农历月 + 农历日 + 时辰序数) mod 8，余 0 取 8；动爻 = (年支序数 + 农历月 + 农历日 + 时辰序数) mod 6，余 0 取 6 |
| 展示 | 起卦参数（如「丙午年 八月十五 午时」）、上/下卦、动爻 |
| 边界 | 农历转换失败时禁止起卦并提示；23:00–01:00 按次日子时处理（详见 03 文档 §6） |

#### FR-02 数字起卦（P0）

| 项目 | 说明 |
| --- | --- |
| 描述 | 用户报两个数字起卦（**仅两数模式**） |
| 两数模式 | 第一数 mod 8 为上卦，第二数 mod 8 为下卦，(第一数 + 第二数) mod 6 为动爻 |
| 输入约束 | 正整数，上限 999,999,999；超出提示；0 视为无效输入并提示「请输入 1 以上的数字」（口径见 03 文档 §6.3，本版不做「按 10 处理」的配置项）；第二数缺失或无效同样拒绝并提示 |
| 边界 | 余 0 取 8 / 取 6 规则与时间起卦一致 |

> **已移除：一数模式**（v2.0 产品决策，编号与本条同属 FR-02，不再单列）。
> 原规则：该数 mod 8 为上卦，(该数 + 当前时辰序数) mod 8 为下卦，(该数 + 时辰序数) mod 6 为动爻。
> 现状：单数输入抛 `CastInputError`（07 文档 TC-N04）；已保存的旧卦例 `inputParams`
> 中 `mode='ONE'` **只读保留、不做迁移回写**（04 文档 §2.4、03 文档 §2.2）。

#### FR-03 汉字笔画起卦（P0）

| 项目 | 说明 |
| --- | --- |
| 描述 | 用户输入**两个汉字**，按笔画数起卦 |
| 两字模式 | 第一字笔画 mod 8 为上卦，第二字笔画 mod 8 为下卦，**（两字笔画和 + 起卦时刻秒钟数）mod 6 为动爻**（余 0 取 6；秒钟数 0–59，见 03 文档 §2.3、§6.5） |
| 展示 | 结果页起卦上下文需展示起卦时刻与秒钟数（如「14:32:06 · 秒 6」），保证动爻可复现 |
| 笔画标准 | 默认简体笔画；设置中可切换为繁体笔画；**同一卦内标准必须统一**，切换标准后需重新起卦 |
| 实现依赖 | 内置汉字笔画数映射表（URO + 扩展 A 全量 27,584 字，单表双标准，见 05 文档 §4），覆盖不到的字提示用户手动输入笔画数 |
| 边界 | 输入非汉字字符（字母/数字/标点）过滤并提示；多音字不影响笔画数 |

> **已移除：一字模式**（v2.0 产品决策）。
> 原规则：笔画总数 mod 8 为上卦，(总数 + 时辰序数) mod 8 为下卦，(总数 + 时辰序数) mod 6 为动爻。
> 现状：单字输入抛 `CastInputError`「汉字数须为 2 个」（07 文档 TC-C03）；已保存的旧卦例
> `inputParams` 中 `mode='ONE'` **只读保留、不做迁移回写**（04 文档 §2.4、03 文档 §2.3）。

#### FR-04 声音（点数）起卦 —— 已移除

> **本条已下线（v1.7 产品决策）**，编号保留不复用，避免历史需求号指向不同的东西。
>
> 原需求：模拟「听几声起卦」——用户听到声音后逐次点按屏幕计数，第一组次数为上卦、
> 第二组为下卦，动爻 = 两组之和 mod 6；单组计数上限 999、至少 1 次。
>
> 处置：起卦方式由五种减为**四种**（时间 / 数字 / 汉字 / 随机）；已保存的旧卦例
> 只读保留、不做迁移回写（03 文档 §2.4 的「已下线」说明）。

#### FR-05 排盘结果展示（P0）

| 项目 | 说明 |
| --- | --- |
| 描述 | 起卦完成后展示完整排盘 |
| 必含要素 | 1) 起卦时间与方式；2) 本卦（卦名 + 卦符 + 上/下卦名）；3) 动爻位置（第几爻 + 爻名如「初六」）；4) 变卦（卦名 + 卦符）；5) 互卦（卦名 + 卦符）；6) 体卦 / 用卦标注；7) 体用五行生克关系与吉凶结论（传统断法 + **程度徽标：大吉 / 小吉 / 吉 / 小凶 / 大凶**，见 03 文档 §1.3） |
| 卦符绘制 | 六爻自下而上存储、自上而下绘制，阳爻「▄▄▄▄▄」实线、阴爻「▄▄ ▄▄」断线，动爻加圆点标记 |
| 附带信息 | 本卦卦辞、动爻爻辞（可展开） |

#### FR-06 断卦辅助信息（P0）

| 项目 | 说明 |
| --- | --- |
| 描述 | 为断卦提供结构化参考信息 |
| 内容 | 1) 体用生克结论卡（核心，含程度分级徽标：大吉/小吉/吉/小凶/大凶，见 03 文档 §1.3）；2) 体卦、用卦的八卦类象（人物/天时/方位等常用类目）；3) 本卦、变卦的**卦意关键词**（手写笔记口径，见 05 文档 §3.5）与卦名含义简注；4) 动爻爻辞原文 |
| 原则 | 只呈现传统文献内容与规则推导结果，**不生成「预测性结论文案」**，最终判断留给用户（兼顾合规，见 §四） |

#### FR-07 卦例记录管理（P0）

| 项目 | 说明 |
| --- | --- |
| 描述 | 卦例的本地持久化管理 |
| 字段 | 起卦时间、起卦方式、输入参数、所问之事（可选）、本/互/变卦、动爻、体用结论、备注（可后期编辑）、应验状态（未验 / 应验 / 未验中 / 不验） |
| 名称 | 列表与详情的显示名称**优先取「所问之事」（占卜目标）**；未填写目标时回退到本卦卦名，再退到「起卦方式 · 农历」（规则与理由见 04 文档 §2.8） |
| 操作 | 保存（起卦页一键存）、查看列表（按时间倒序）、搜索（按所问之事/卦名/备注关键字）、编辑备注、标记应验、删除（二次确认） |
| 存储 | 本地数据库，完全离线。Web 端 IndexedDB，Android 端 Room（详见 04 文档 §二） |

#### FR-08 卦例导出（P1）

导出为 JSON（完整字段）或 CSV（面向表格查看）。Android 端通过系统分享面板保存或发送；Web 端触发浏览器下载（CSV 带 UTF-8 BOM，避免 Excel 乱码）。

#### FR-09 学习资料页（P1）

| 内容块 | 说明 |
| --- | --- |
| 八卦类象速查 | 八卦 × 类象类目的二维速查表 |
| 六十四卦速查 | 64 卦列表（卦名、卦符、上下卦组合、卦辞），支持按上/下卦过滤 |

> **已移除：起卦方法说明**内容块（v2.0 产品决策）——学习页只保留上表两个速查块；
> 算法规则仍以 03 文档为唯一权威，不再在应用内重复呈现。

#### FR-10 设置（P0）

| 设置项 | 取值 | 默认值 |
| --- | --- | --- |
| 笔画标准 | 简体 / 繁体 | 简体 |
| 默认起卦方式 | 时间 / 数字 / 汉字 | 时间 |
| 体用判定规则 | 动爻所在为用（通行）/ 上卦恒为用（手写笔记流派） | 动爻所在为用 |
| 主题 | 浅色 / 深色 / 跟随系统 | 跟随系统 |

## 三、用户流程

### 3.1 主流程（时间起卦为例）

```
打开 App
  → 【起卦】Tab（默认时间起卦，显示当前农历时间预览）
  → 点击「起卦」
  → 排盘结果页（本卦/动爻/互卦/变卦/体用/生克结论）
  → 可选：填写「所问之事」→ 保存卦例
  → 可选：查看卦辞 / 动爻爻辞 / 类象详情
```

### 3.2 卦例复盘流程

```
【卦例】Tab → 列表（时间倒序）→ 搜索或筛选
  → 卦例详情 → 编辑备注 / 标记应验 / 删除
  → 可选：导出 JSON/CSV
```

## 四、非功能需求

| 编号 | 类别 | 要求 |
| --- | --- | --- |
| NFR-01 | 性能 | 起卦计算 + 排盘渲染 ≤ 200ms；冷启动 ≤ 2s（中端机 / 中端手机浏览器） |
| NFR-02 | 离线 | 全功能离线可用。Web 端为纯静态站点，不含任何后端接口调用；Android 端不申请网络权限 |
| NFR-03 | 隐私 | 不收集任何用户数据，无账号体系，无第三方 SDK（统计/广告均不接入）；隐私政策声明「所有数据仅存储在本机」 |
| NFR-04 | 兼容 | Web 端：Chrome / Edge / Safari / Firefox 近两年版本，含 iOS Safari 与 Android Chrome；排版须自适应（详见 06 文档 §6.2）。Android 端：minSdk 26（Android 8.0），targetSdk 35，覆盖主流国产 ROM（小米/华为/OPPO/vivo） |
| NFR-05 | 可靠性 | 农历转换必须覆盖**全支持范围**（1900–2100）的逐日校验：字段不变量 + 公↔农往返一致性，见 07 测试计划 TC-LC08（实际穷举 73,384 天；跨实现对拍为 Android 阶段准入项 TC-LC04b） |
| NFR-06 | 可维护性 | 起卦算法与知识库数据均为纯逻辑 + 纯数据（Web 端 TypeScript / Android 端 Kotlin + JSON 资产），可独立单测；两端共享同一份知识库数据与算法口径 |
| NFR-07 | 国际化 | 第一版仅简体中文；文案集中管理（Web 端组件内常量 / Android 端 strings.xml），预留多语言扩展 |

## 五、合规风险与对策（重要）

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| 应用市场审核 | 国内主流应用市场（华为/小米/OPPO/vivo 等）对「占卜、算命、封建迷信」类应用审核严格，直接以「算卦」为卖点大概率被拒 | 产品描述与 UI 文案统一使用「传统文化 / 国学学习 / 易经知识工具」表述；功能上提供卦辞爻辞查阅等学习型价值；应用截图避免「预测吉凶」宣传语 |
| 内容表述 | 「断吉凶」类绝对化表述有合规风险 | 界面文案用「体用生克关系：体生用（传统断法：小凶，主耗损）」这类**规则陈述**，不输出「你将会……」的预测性断言；首次启动展示「仅供传统文化学习研究」声明页 |
| 支付与商业化 | 以占卜为名的诱导付费属于高危 | 第一版不接入任何付费/广告；后续如需商业化，仅限「知识内容付费 / 周边文创」类目 |
| Google Play | 海外渠道对占卜类相对宽松 | 海外版（Plumora）可正常以 divination 类目上架，文案区分国内外两套 |
