## 一、端与共享层划分

产品形态为 **Web + Android 双端**，两端共用同一套「起卦算法口径 + 卦象知识库数据」，仅在**平台能力**（日历转换、持久化、UI 渲染）上各自实现。

```
                 ┌──────────────────────────────┐
                 │  共享层（纯逻辑，无平台依赖）    │
                 │  knowledge  64 卦 / 8 卦类象   │
                 │  core       起卦 / 推导 / 生克  │
                 └──────────────┬───────────────┘
                                │
             ┌──────────────────┴──────────────────┐
             ▼                                     ▼
  ┌──────────────────────┐              ┌──────────────────────┐
  │ Web 端（当前阶段）     │              │ Android 端（后续阶段）  │
  │ Vue 3 + TypeScript   │              │ Kotlin + Compose     │
  │ ├ lunar  solarlunar  │              │ ├ lunar  lunar-java  │
  │ ├ 持久化 IndexedDB    │              │ ├ 持久化 Room         │
  │ └ 设置  localStorage  │              │ └ 设置  DataStore     │
  └──────────────────────┘              └──────────────────────┘
```

**共享层的边界**：只包含**纯函数**与**纯数据**，不引用 `window` / `document` / `indexedDB` 等任何宿主对象。平台差异一律通过端口（interface）注入，见 §三。

## 二、技术选型

### 2.1 Web 端（当前阶段）

| 类别 | 选型 | 版本基线 | 选择理由 |
| --- | --- | --- | --- |
| 语言 | TypeScript | 5.9+ | 与共享层同构；`strict` + `verbatimModuleSyntax` |
| UI 框架 | Vue 3 | 3.5+ | `<script setup>` 语法简洁、SFC 单文件利于移植；运行时体积小 |
| 构建 | Vite | 7.x | 开箱即用 TS/SFC，产物为纯静态文件，可任意静态托管；构建时把产品版本写入产物（`<html data-app-version>` + `<meta name="app-version">`），便于部署后核对线上版本 |
| 路由 | 自持 hash 路由（约 60 行） | — | 仅需 3 Tab + 2 详情；避免引入 vue-router，且 hash 路由在静态托管（含子目录部署）下无需服务端 rewrite |
| 本地数据库 | IndexedDB（原生 API，无 wrapper） | — | 等价替代 Android 的 Room，见 04 文档 §二 |
| 键值配置 | localStorage | — | 等价替代 Android 的 DataStore，见 04 文档 §三 |
| 农历转换 | solarlunar | 2.0+ | 内置 1900–2100 农历数据表，零依赖；与 Android 端 lunar-java 需对拍验证（见 07 文档 §3.4） |
| 汉字笔画 | 自建映射表（TS 常量） | — | 与 Android 端共用同一份字表内容；覆盖不到的字允许手动输入兜底 |
| 样式 | 原生 CSS + CSS 自定义属性 | — | 设计令牌走 CSS 变量，主题切换只改 `<html data-theme>`；不引入 UI 组件库，避免样式体系被绑定 |
| 测试 | Vitest（单测）+ jsdom（运行时冒烟） | 3.x / 30.x | 与 Vite 共用配置与路径别名；单测覆盖纯逻辑，jsdom 冒烟覆盖「组件挂载即白屏」 |

**明确不引入**：任何后端服务、任何网络请求库、任何统计 / 广告 SDK、任何 UI 组件库。Web 端产物为纯静态资源，不含对外接口调用（NFR-02）。

### 2.2 Android 端（后续阶段）

| 类别 | 选型 | 版本基线 | 选择理由 |
| --- | --- | --- | --- |
| 语言 | Kotlin | 2.0+ | Android 官方首选，协程与空安全 |
| UI | Jetpack Compose + Material 3 | BOM 2024.09+ | 声明式 UI 适合排盘动态渲染与主题切换 |
| 架构模式 | MVVM + 单向数据流（UDF） | — | 与 Compose 天然契合 |
| 依赖注入 | Hilt | 2.51+ | 标准化 DI，与 ViewModel 集成好 |
| 本地数据库 | Room | 2.6+ | 卦例记录持久化，SQLite 之上类型安全 |
| 键值配置 | DataStore (Preferences) | 1.1+ | 轻量设置存储，Flow 响应式 |
| 异步 | Kotlin Coroutines + Flow | — | 标准异步方案 |
| 序列化 | kotlinx.serialization | 1.7+ | 知识库资产解析、导出文件生成 |
| 农历转换 | lunar-java（6tail/lunar-java） | 1.7+ | 成熟农历/干支库，避免自造轮子出错；需与 Web 端对拍验证（见 07 文档 §3.4） |
| 汉字笔画 | 自建映射表（assets JSON） | — | 无可靠开源库，自建并允许手动输入兜底 |
| 测试 | JUnit5 + Turbine + Compose UI Test | — | 算法纯函数为主，单测覆盖率高 |
| 构建 | Gradle 8.x + Kotlin DSL + Version Catalog | AGP 8.5+ | 标准化构建 |

**明确不引入**：网络库（Retrofit/OkHttp）、图片加载库（Coil 可选仅用于分享图）、Firebase / 统计 SDK。应用不申请 `INTERNET` 权限（NFR-02/03）。

## 三、共享层与平台端口

共享层定义端口，各端注入实现——这是「一套算法口径、两端各自落地」的关键。

| 端口（定义在共享层） | Web 端实现 | Android 端实现 | 说明 |
| --- | --- | --- | --- |
| `LunarProvider` | `solarlunar` 封装 | `lunar-java` 封装 | 公历 → 农历（年支序数/月/日/时辰序数） |
| 卦例仓储 | IndexedDB | Room DAO | 字段契约完全一致，见 04 文档 §2.2 |
| 设置仓储 | localStorage | DataStore | 设置项与默认值完全一致，见 04 文档 §三 |

其余（起卦、卦象推导、五行生克、记录组装与回放）**全部在共享层**，两端不重写。

## 四、工程结构（monorepo）

采用 npm workspaces 单仓多包：`packages/*` 为共享层，`apps/*` 为各端应用。

```
Plumora/
├─ start.bat                     # 一键启动（纯 ASCII 壳，转交 start.ps1；见 §六 工程约定）
├─ start.ps1                     # 一键启动逻辑（UTF-8 with BOM）
├─ version.json                  # 版本号单一真源（Web + Android 共用，见 08 文档 §一）
├─ CHANGELOG.md                  # 产品版本变更记录
├─ package.json                  # workspaces 根：packages/*、apps/*
├─ tsconfig.base.json            # 全仓 TS 基线（strict / verbatimModuleSyntax / noEmit）
├─ scripts/version.mjs           # 版本号 show / check / sync / bump
├─ packages/
│  ├─ knowledge/                 # 卦象知识库（纯数据，零依赖）
│  │  └─ src/  trigrams.ts  hexagrams.ts  strokes.ts
│  ├─ core/                      # 起卦与推导（纯逻辑）
│  │  └─ src/  types.ts  modulus.ts  casters.ts  resolve.ts  judge.ts
│  │           line.ts  lunar.ts（端口定义）  record.ts
│  └─ lunar/                     # 农历适配（Web 实现，注入 LunarProvider）
│     └─ src/  index.ts  solarlunar.d.ts
└─ apps/
   └─ web/                       # Web 应用（Vue 3 + Vite）
      ├─ build/aliases.ts        # vite / vitest 共用路径别名（直指 packages 源码）
      ├─ vite.config.ts          # 常规构建（产物 apps/web/dist，base: './'）
      ├─ vite.smoke.config.ts    # 运行时冒烟构建（单文件 IIFE）
      ├─ scripts/runtime-smoke.cjs  # jsdom 运行时冒烟（逐路由断言 + 零错误）
      ├─ index.html
      ├─ test/                   # Vitest 单测（路由 / 设置 / 导出 / 排盘暂存）
      └─ src/
         ├─ generated/version.ts # ⚠️ 由 scripts/version.mjs 生成，勿手工编辑
         ├─ styles/              # tokens.css 设计令牌 / base.css 原语 / glyph.css 卦符
         ├─ platform/            # 平台能力：settings.ts、records.ts
         ├─ stores/              # 响应式状态：settings、records、cast、toast
         ├─ components/          # HexagramGlyph、ResultPanel、SegControl 等
         ├─ views/               # CastView、ResultView、RecordsView、RecordDetailView、LearnView
         ├─ router.ts            # 自持 hash 路由
         └─ App.vue              # 自适应外壳（断点 900px）
```

**别名策略**：Web 端通过路径别名直接引用 `packages/*/src/index.ts` 源码，不做预构建。改动共享层代码无需重新打包，两端也天然共享同一份口径。

**与 Android 端的对应**：`packages/knowledge` 的 TS 常量即 Android `assets/knowledge/*.json` 的内容来源；`packages/core` 的每个导出函数在 Android 端有同名 Kotlin 实现，口径以 03 文档为准。

## 五、关键流程

### 5.1 起卦流程（时序）

```
用户点击「起卦」
  → CastView 收集输入（CastInput）
  → 共享层具体 Caster（如 castByTime）:
      1. LunarProvider 取农历字段（年支序数/月/日/时辰序数）
      2. 按 mod 8 / mod 6 规则计算 upper / lower / movingLine
      3. 返回 CastResult（含中间量 params 与起卦标签 label）
  → 共享层 resolve(raw, tiYongRule):
      1. 组合本卦（上卦+下卦），查知识库得卦名
      2. 互卦 = 本卦 2,3,4 爻为下卦、3,4,5 爻为上卦
      3. 变卦 = 动爻取反后的六爻组合
      4. 体用 = 按 tiYongRule 判定（默认「动爻所在为用」）
  → 共享层 judge(ti, yong):
      按五行生克表输出关系与程度（大吉/小吉/吉/小凶/大凶）
  → stores/cast 暂存结果 → 跳转结果页渲染
```

### 5.2 卦例保存流程

```
结果页点击「保存」
  → stores/cast 的 CastResult + ResolvedHexagram
  → 共享层 buildRecord() 组装 HexagramRecord（含 tiYongRule）
  → platform/records 写入 IndexedDB（Web）/ Room（Android）
  → 列表页 onActivated 重新查询并渲染
```

### 5.3 数据流约定

- **共享层不依赖任何 UI / 存储类型**：输入是纯参数对象，输出是纯结果对象。
- **Web 端状态**：`stores/*` 用 Vue `reactive`/`ref` 单例；视图只读状态，写操作统一走 `platform/*`。
- **Web 端排盘暂存**：只持久化「起卦输入 + 生效流派」，重新推导结果（`materialize`），使知识库更新后历史会话同步到最新口径；而**已落库的卦例**则用落库的 `tiTrigram`/`yongTrigram` 回放（见 04 文档 §2.2），不随设置漂移。

## 六、工程约定

| 项 | 约定 |
| --- | --- |
| Web 端 SDK | Node ≥ 20.19（构建期）；产物为 ES2022 静态资源 |
| Android 端 SDK | minSdk 26 / targetSdk 35 / compileSdk 35 |
| JDK | 17（Gradle 工具链） |
| Android 包名 | com.plumora.guanmei |
| versionCode / versionName | 见 08-版本计划与发布规范.md |
| 版本号 | **单一真源**：仓根 `version.json`，Web 与 Android 共用。派生目标由 `scripts/version.mjs` 写入（5 个 package.json、Web 端 TS 常量、Android versionName/versionCode），`npm run version:check` 逐字节校验（见 08 文档 §一） |
| 命名 | 域名词优先（Hexagram、Trigram、Yao），避免拼音缩写；「卦」相关统一用拼音注释辅助 |
| 错误处理 | 共享层抛出具名错误（如 `CastInputError`），各端在 UI 边界统一映射提示文案 |
| 日志 | Web 端不使用 `console` 输出业务信息；Android 端仅 Debug 构建输出 Timber 日志，Release 关闭 |
| 混淆 | Android Release 开启 R8，rules 保护 kotlinx.serialization 与 Room |
| 仓根 `package.json` | **不设 `"type": "module"`**。各 workspace 包自带 `"type": "module"`；仓根若设该字段，会把 `.workbuddy/checks/*.js` 这些既有 CommonJS 工具链一并当成 ESM，导致检查脚本无法运行 |
| Windows 脚本编码 | `start.bat` 保持**纯 ASCII**：`cmd.exe` 用当前控制台代码页解析整个批处理文件，含中文的 UTF-8 `.bat` 会被按 GBK 截成乱码命令（存 GBK 可用，但用户开启 Windows UTF-8 控制台选项后再次失效）。中文逻辑一律放 `.ps1`，存为 **UTF-8 with BOM**（Windows PowerShell 5.1 只在看到 BOM 时才按 UTF-8 解析）。`.gitattributes` 对 `*.bat` / `*.cmd` / `*.ps1` 锁定 `eol=crlf`——LF-only 的批处理文件会让 `goto` / 标签解析出错 |

## 七、依赖关系图（共享层视角）

```
knowledge ← core.types ← core.casters   ← apps/web（CastView）
knowledge ← core.resolve ←┘
knowledge ← core.judge   ←┘
core.lunar（端口）──→ core.casters      （农历字段供给，各端注入实现）
core.record ──→ apps/web/platform.records（落库契约）
core.record ──→ Android Room entity     （字段一一对应）
```

共享层对知识库的依赖为**直接引用纯数据模块**（无 I/O、无异步）；对农历的依赖为**接口**（`LunarProvider`），保证共享层可脱离任何宿主环境单测。
