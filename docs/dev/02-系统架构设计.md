## 一、技术选型

| 类别 | 选型 | 版本基线 | 选择理由 |
| --- | --- | --- | --- |
| 语言 | Kotlin | 2.0+ | Android 官方首选，协程与空安全 |
| UI | Jetpack Compose + Material 3 | BOM 2024.09+ | 声明式 UI 适合排盘动态渲染与主题切换 |
| 架构模式 | MVVM + 单向数据流（UDF） | — | 与 Compose 天然契合 |
| 依赖注入 | Hilt | 2.51+ | 标准化 DI，与 ViewModel 集成好 |
| 本地数据库 | Room | 2.6+ | 卦例记录持久化，SQLite 之上类型安全 |
| 键值配置 | DataStore (Preferences) | 1.1+ | 轻量设置存储，Flow 响应式 |
| 异步 | Kotlin Coroutines + Flow | — | 标准异步方案 |
| 序列化 | kotlinx.serialization | 1.7+ | 知识库 JSON 资产解析、导出文件生成 |
| 农历转换 | lunar-java（6tail/lunar-java） | 1.7+ | 成熟农历/干支库，避免自造轮子出错；需对拍验证（见 07） |
| 汉字笔画 | 自建映射表（assets JSON） | — | 无可靠开源库，自建并允许手动输入兜底 |
| 测试 | JUnit5 + Turbine + Compose UI Test | — | 算法纯函数为主，单测覆盖率高 |
| 构建 | Gradle 8.x + Kotlin DSL + Version Catalog | AGP 8.5+ | 标准化构建 |

**明确不引入**：网络库（Retrofit/OkHttp）、图片加载库（Coil 可选仅用于分享图）、Firebase / 统计 SDK。应用不申请 `INTERNET` 权限（NFR-02/03）。

## 二、整体架构

### 2.1 分层架构

```
┌─────────────────────────────────────────────┐
│  UI 层（Compose Screen + ViewModel）          │
│  起卦页 / 排盘结果页 / 卦例列表 / 卦例详情      │
│  学习资料页 / 设置页                           │
├─────────────────────────────────────────────┤
│  Domain 层（纯 Kotlin，无 Android 依赖）       │
│  CastEngine（起卦引擎）                       │
│  ├─ TimeCaster / NumberCaster                │
│  ├─ CharacterCaster / SoundCaster            │
│  HexagramResolver（卦象推导：互/变/体用）      │
│  FiveElementJudge（五行生克判定）             │
├─────────────────────────────────────────────┤
│  Data 层                                     │
│  Room（HexagramRecord）                      │
│  DataStore（设置）                            │
│  KnowledgeRepository（assets JSON 知识库）    │
│  LunarCalendarProvider（lunar-java 封装）     │
└─────────────────────────────────────────────┘
```

### 2.2 模块划分

第一版采用**单 module（app）+ 包分层**，降低早期维护成本；Domain 包保持纯 Kotlin（`kotlin-only` 源集），为日后拆 multi-module 预留。

```
app/
└─ src/main/java/com/plumora/guanmei/
   ├─ GuanmeiApp.kt                 // @HiltAndroidApp
   ├─ MainActivity.kt
   ├─ ui/
   │  ├─ navigation/                // NavHost 与路由
   │  ├─ cast/                      // 起卦页
   │  ├─ result/                    // 排盘结果页
   │  ├─ records/                   // 卦例列表 + 详情
   │  ├─ learn/                     // 学习资料页
   │  └─ settings/                  // 设置页
   ├─ domain/
   │  ├─ caster/                    // 各起卦方法实现
   │  ├─ resolver/                  // 卦象推导
   │  ├─ judge/                     // 五行生克
   │  └─ model/                     // CastInput / Hexagram / Trigram 等纯模型
   ├─ data/
   │  ├─ db/                        // Room: entity / dao / database
   │  ├─ datastore/                 // SettingsRepository
   │  ├─ knowledge/                 // 知识库 JSON 加载与仓库
   │  └─ lunar/                     // LunarCalendarProvider
   ├─ export/                       // JSON/CSV 导出
   └─ di/                           // Hilt modules
└─ src/test/                        // Domain 层单测（重点）
└─ src/androidTest/                 // Room DAO 测试、Compose UI 测试
assets/
└─ knowledge/
   ├─ trigrams.json                 // 八卦基础数据

   ├─ strokes_simplified.json       // 简体笔画映射
   └─ strokes_traditional.json      // 繁体笔画映射
```

## 三、关键流程

### 3.1 起卦流程（时序）

```
用户点击「起卦」
  → CastViewModel.cast(CastInput)
  → 具体 Caster（如 TimeCaster）:
      1. LunarCalendarProvider 取农历字段（年支序数/月/日/时辰序数）
      2. 按 mod 8 / mod 6 规则计算 upperNum / lowerNum / movingLine
      3. 返回 RawCast(upperTrigram, lowerTrigram, movingLine, params)
  → HexagramResolver.resolve(raw):
      1. 组合本卦（上卦+下卦），查知识库得卦名
      2. 互卦 = 本卦 2,3,4 爻为下卦、3,4,5 爻为上卦
      3. 变卦 = 动爻取反后的六爻组合
      4. 体用 = 动爻在上卦→上卦为用/下卦为体；在下卦→下卦为用/上卦为体
  → FiveElementJudge.judge(ti, yong):
      按五行生克表输出关系与结论
  → UI 渲染排盘结果页
```

### 3.2 卦例保存流程

```
结果页点击「保存」
  → RecordsViewModel.save(hexagram, question?)
  → HexagramRecordDao.insert()
  → Toast/.snackbar 反馈成功；卦例列表 Flow 自动刷新
```

### 3.3 数据流约定

- UI → ViewModel：一次性事件用函数调用，状态用 `StateFlow`。
- ViewModel → UI：`StateFlow<UiState>` 单一状态对象（含 loading/error/data）。
- Data → Domain：DAO 返回 `Flow<List<HexagramRecord>>`，Domain 不依赖 Room 类型（实体在 data 层，domain 用纯模型 + mapper）。

## 四、工程约定

| 项 | 约定 |
| --- | --- |
| SDK | minSdk 26 / targetSdk 35 / compileSdk 35 |
| JDK | 17（Gradle 工具链） |
| 包名 | com.plumora.guanmei |
| versionCode / versionName | 见 08-版本计划与发布规范.md |
| 命名 | 域名词优先（Hexagram、Trigram、Yao），避免拼音缩写；「卦」相关统一用拼音注释辅助 |
| 错误处理 | Domain 层用 sealed Result（CastResult.Success / Failure(reason)），UI 统一映射提示文案 |
| 日志 | 仅 Debug 构建输出 Timber 日志；Release 关闭 |
| 混淆 | Release 开启 R8，rules 保护 kotlinx.serialization 与 Room |

## 五、依赖关系图（Domain 视角）

```
domain.model ← domain.caster ← CastViewModel
domain.model ← domain.resolver ←┘
domain.model ← domain.judge  ←┘
domain.lunar ──→ domain.caster （农历字段供给）
data.knowledge ──→ domain.resolver （卦名/卦辞查询接口由 domain 定义、data 实现）
data.db ──→ ui.records
```

Domain 层对知识库的依赖通过接口 `HexagramCatalog` 抽象，Data 层用 assets JSON 实现，保证 Domain 可脱离 Android 单测。
