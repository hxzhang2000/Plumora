## 一、基础约定

### 1.1 先天八卦数与卦符

| 数 | 卦名 | 卦符（Unicode） | 爻结构（自下而上，1=阳 0=阴） | 五行 | 二进制编码（下爻为最低位） |
| --- | --- | --- | --- | --- | --- |
| 1 | 乾 ☰ | U+2630 | [1,1,1] | 金 | 0b111 = 7 |
| 2 | 兑 ☱ | U+2631 | [1,1,0] | 金 | 0b011 = 3 |
| 3 | 离 ☲ | U+2632 | [1,0,1] | 火 | 0b101 = 5 |
| 4 | 震 ☳ | U+2633 | [1,0,0] | 木 | 0b001 = 1 |
| 5 | 巽 ☴ | U+2634 | [0,1,1] | 木 | 0b110 = 6 |
| 6 | 坎 ☵ | U+2635 | [0,1,0] | 水 | 0b010 = 2 |
| 7 | 艮 ☶ | U+2636 | [0,0,1] | 土 | 0b100 = 4 |
| 8 | 坤 ☷ | U+2637 | [0,0,0] | 土 | 0b000 = 0 |

**程序内部表示**：卦用 `Int` 位编码（下爻 = bit0），爻列表用 `List<Int>`（index 0 = 初爻）。**存储与计算一律自下而上，仅绘制时反转为自上而下显示**。

### 1.2 取余规则（全方法通用）

| 项 | 规则 |
| --- | --- |
| 上卦 / 下卦 | 数值 mod 8；**余 0 时取 8** |
| 动爻 | 数值 mod 6；**余 0 时取 6** |
| 动爻序号 | 1 = 初爻（最下），6 = 上爻（最上） |

### 1.3 五行与生克

卦 → 五行：乾兑属金，离属火，震巽属木，坎属水，艮坤属土。

| 关系 | 五行含义 | 传统断法 | 程度分级（手写笔记口径） |
| --- | --- | --- | --- |
| 用生体 | 用卦五行生体卦五行 | 吉，有外力帮助 | **大吉** |
| 体克用 | 体卦五行克用卦五行 | 吉，能掌控局面 | **小吉** |
| 体用比和 | 五行相同 | 吉，顺利和谐 | 吉 |
| 体生用 | 体卦五行生用卦五行 | 小凶，耗损精力 | **小凶** |
| 用克体 | 用卦五行克体卦五行 | 凶，受制于人 | **大凶** |

> 程度分级来源：手写笔记 `docs/reference/1164309e0e9022e8fcc6b2e4f93ec212.jpg`（用生体大吉、体克用小吉、体生用小凶、用克体大凶）。比和一条笔记未标注程度，按传统取「吉」。UI 展示时同时给出「传统断法文案 + 程度徽标（大吉/小吉/吉/小凶/大凶）」。

五行生克矩阵（行生列 / 行克列需分别查表）：

| 生 | 木→火，火→土，土→金，金→水，水→木 |
| --- | --- |
| 克 | 木克土，土克水，水克火，火克金，金克木 |

## 二、起卦方法实现

### 2.1 时间起卦法（年月日时）

**参数定义**：

| 参数 | 取值 | 来源 |
| --- | --- | --- |
| 年数 Y | 农历年**地支序数**：子=1，丑=2，……，亥=12 | 取农历年（`lYear`）地支，查表得序数；**年界口径见 §6.1** |
| 月数 M | 农历月份数字（正月=1……腊月=12） | 闰月处理见 §6.1 |
| 日数 D | 农历日数字（初一=1……三十=30） | — |
| 时数 H | 时辰序数：子时=1，丑时=2，……，亥时=12 | 时辰划分见 §6.2 |

**计算**：

```
S1 = Y + M + D
upper = S1 mod 8  （余0取8）
S2 = S1 + H
lower = S2 mod 8  （余0取8）
moving = S2 mod 6 （余0取6）
```

**金标准算例 A**（来自需求依据）：农历 2026 年八月十五日午时。

```
Y = 午 = 7，M = 8，D = 15，H = 午 = 7
S1 = 7 + 8 + 15 = 30；30 mod 8 = 6 → 上卦坎
S2 = 30 + 7 = 37；37 mod 8 = 5 → 下卦巽
moving = 37 mod 6 = 1 → 第 1 爻（初爻）动
本卦 = 坎上巽下 = 水风井
变卦 = 初爻变（巽[0,1,1] 初爻 0→1 = 乾）= 坎上乾下 = 水天需
体用 = 动爻在下卦 → 下卦巽为用，上卦坎为体
生克 = 坎水生巽木 → 体生用 → 小凶
```

### 2.2 数字起卦法

**两数模式**（n1、n2 均为正整数）：

```
upper = n1 mod 8（余0取8）
lower = n2 mod 8（余0取8）
moving = (n1 + n2) mod 6（余0取6）
```

> **已移除：一数模式**（原 §2.2 第二小节，v2.0 移除）。
>
> 原规则：n 为正整数、H 为当前时辰序数，`upper = n mod 8`、`S = n + H`、
> `lower = S mod 8`、`moving = S mod 6`（余 0 取 8 / 6）。
>
> 产品决策不再提供单数输入，数字起卦**仅剩两数模式**：`castByNumber(n1, n2)`
> 第二数缺失或无效即抛 `CastInputError`（「第二数无效」），07 文档 **TC-N04** 按此断言；
> 原 TC-N05（一数模式时辰非整数）随模式一并下线，用例号不再复用。
> **旧卦例只读保留**：库里 `inputParams` 中 `mode='ONE'` 的记录不做迁移回写，
> 详情页照常复现（04 文档 §2.4）。

### 2.3 汉字笔画起卦法

**两字模式**（A = 第一字笔画数，B = 第二字笔画数，S = 起卦时刻秒钟数 0–59）：

```
upper = A mod 8（余0取8）
lower = B mod 8（余0取8）
moving = (A + B + S) mod 6（余0取6）
```

> 动爻规则 v1.2 起变更：两字笔画之和**追加秒钟数**再对 6 取余。目的：相同的两个字在不同时刻起卦可得到不同动爻，避免「同字必然同卦」。秒钟数取起卦瞬间系统时间的秒位（0–59），在结果页起卦上下文中展示。本变更**仅作用于两字模式**，口径见 §6.5。

> **已移除：一字模式**（原 §2.3 第二小节，v2.0 移除）。
>
> 原规则：T 为该字笔画总数、H 为时辰序数，`upper = T mod 8`、`S = T + H`、
> `lower = S mod 8`、`moving = S mod 6`（不加秒，原 §6.5 口径）。
>
> 产品决策不再提供单字输入，汉字笔画起卦**仅剩两字模式**：`castByCharacter()`
> 只接受 2 个汉字，`chars` / `strokes` 不等于 2 即抛 `CastInputError`（「汉字数须为
> 2 个」），07 文档 **TC-C03** 按此断言；原 TC-C08（一字模式时辰非整数）随模式一并
> 下线，用例号不再复用。**旧卦例只读保留**：`mode='ONE'` 的记录不做迁移回写
> （04 文档 §2.4）。

**拆字模式（进阶）**：将字按结构拆为上下或左右两部分，分别数笔画作为 A、B 走两字模式。第一版实现为「用户手动输入拆分后两部分笔画」，不做自动拆字。

**金标准算例 B**（来自需求依据，v1.2 起含秒钟数）：取「梅」「花」，繁体笔画 A=11、B=8，起卦时刻秒钟数 S=6。

```
upper = 11 mod 8 = 3 → 离
lower = 8 mod 8 = 0 → 取 8 → 坤
moving = (11 + 8 + 6) = 25；25 mod 6 = 1 → 初爻动
本卦 = 离上坤下 = 火地晋
变卦 = 初爻变（坤[0,0,0] 初爻 0→1 = 震）= 离上震下 = 火雷噬嗑
互卦 = 本卦 2,3,4 爻为下卦、3,4,5 爻为上卦 → 水山蹇
体用 = 上卦离为体（不动），下卦坤为用（动）
生克 = 体离火生用坤土 → 体生用 → 小凶
```

> 算例 B 取 S=6 后动爻仍为初爻，与需求原文算例（未含秒数时 19 mod 6 = 1）结论一致，可作为回归基准；S 取其他值时动爻按公式平移。

### 2.4 随机起卦法（P2，模拟「外应」）

提供「摇一摇 / 点击随机」入口，内部用 `SecureRandom` 生成 1–8、1–8、1–6 三个数分别作为上卦、下卦、动爻。结果页需标注「随机起卦」以与正统方法区分。

> **已下线：声音（点数）起卦**（原 §2.4，v1.7 移除）。
>
> 原规则：用户点按计数得 c1（上）、c2（下），`upper = c1 mod 8`、`lower = c2 mod 8`、
> `moving = (c1 + c2) mod 6`（余 0 取 8 / 6），即规则与两数模式同形。
>
> 产品决策不再提供该方式，`CastMethod` 已不含 `SOUND`。**旧卦例只读保留**：
> 库里已有的 `method='SOUND'` 记录不做迁移回写，展示一律走 `methodCn()` 容错回退为
> 「其他方式」；设置里残留的 `defaultCastMethod='SOUND'` 在载入时回落为 `TIME`
> （否则起卦页三项方式全不选中、点「起卦」无反应）。
>
> 若日后要恢复该方式，须同时改：本文档 §2 章序、`packages/core/src/types.ts` 的
> `CastMethod` / `METHOD_CN` / `InputParams`、`casters.ts` 的起卦函数，以及 07 文档用例表。

## 三、卦象推导

### 3.1 本卦

`本卦六爻 = 下卦三爻 + 上卦三爻`（自下而上拼接：index 0–2 为下卦，index 3–5 为上卦）。

### 3.2 动爻

`moving ∈ [1,6]`，对应爻列表 index = moving - 1。爻名按 §3.5 命名。

### 3.3 变卦

将本卦动爻取反（0↔1），其余五爻不变，得到六爻组合 → 上三爻为变卦上卦、下三爻为变卦下卦 → 查知识库得卦名。

### 3.4 互卦

| 互卦组成 | 取自本卦爻位（自下而上编号 1–6） | 说明 |
| --- | --- | --- |
| 互卦下卦 | 本卦第 2、3、4 爻 | 拼为三爻 |
| 互卦上卦 | 本卦第 3、4、5 爻 | 拼为三爻 |

注意第 3、4 爻在上下两半中**复用**。

**验证（算例 B）**：本卦火地晋六爻自下而上 = [0,0,0,1,0,1]（下坤[0,0,0] + 上离[1,0,1]）。第 2,3,4 爻 = [0,0,1] = 艮（互下卦）；第 3,4,5 爻 = [0,1,0] = 坎（互上卦）→ 互卦坎上艮下 = **水山蹇** ✓。

> **口径更正（v1.3）**：需求原文算例将本例互卦标注为「山水蒙」，但按本表「二三四爻为互下卦、三四五爻为互上卦」的通行构造规则，结果应为水山蹇（坎上艮下）。通行口径已用经典事实验证：水火既济互卦 = 火水未济。原标注系来源笔误，本系统按水山蹇实现；同理，水风井互卦为火泽睽（离上兑下），而非泽火革。

### 3.5 爻名命名规则

| 规则 | 说明 |
| --- | --- |
| 阳爻称「九」，阴爻称「六」 | — |
| 第 1 爻称「初」，第 6 爻称「上」 | 如初九、初六、上九、上六 |
| 第 2–5 爻称「二 / 三 / 四 / 五」 | 如九二、六三、九四、六五 |

示例：初六（第 1 爻阴爻动）、上九（第 6 爻阳爻动）、六三（第 3 爻阴爻）。

### 3.6 体用判定

通行规则（默认，与需求两算例一致）：

```
若 moving ∈ [4,6]：动爻在上卦 → 上卦为用卦，下卦为体卦
若 moving ∈ [1,3]：动爻在下卦 → 下卦为用卦，上卦为体卦
```

流派变体（手写笔记口径「上为用、下为体」）：

```
不问动爻位置，上卦恒为用卦、下卦恒为体卦
```

两种规则通过设置项 `ti_yong_rule` 切换（`MOVING_LINE` 默认 / `UPPER_YONG_LOWER_TI`），见 §八 与 04 文档 DataStore 设置表。

## 五、参考实现骨架（Kotlin）

```kotlin
// 卦编码：下爻为 bit0
enum class Trigram(val number: Int, val binary: Int, val element: Element) {
    QIAN(1, 0b111, Element.METAL), DUI(2, 0b011, Element.METAL),
    LI(3, 0b101, Element.FIRE),    ZHEN(4, 0b001, Element.WOOD),
    XUN(5, 0b110, Element.WOOD),   KAN(6, 0b010, Element.WATER),
    GEN(7, 0b100, Element.EARTH),  KUN(8, 0b000, Element.EARTH);

    val lines: List<Int> get() = List(3) { (binary shr it) and 1 }
    companion object {
        fun byNumber(n: Int): Trigram = entries.first { it.number == n }
    }
}

fun modTrigram(n: Long): Int { val r = (n % 8).toInt(); return if (r == 0) 8 else r }
fun modMoving(n: Long): Int  { val r = (n % 6).toInt(); return if (r == 0) 6 else r }

fun resolveHexagram(
    upper: Trigram,
    lower: Trigram,
    moving: Int,
    tiYongRule: TiYongRule = TiYongRule.MOVING_LINE   // 体用判定流派，见 §3.6 与 04 文档 DataStore 设置表
): ResolvedHexagram {
    val lines = lower.lines + upper.lines          // index0 = 初爻
    val changed = lines.mapIndexed { i, v -> if (i == moving - 1) 1 - v else v }
    val bianLower = Trigram.entries.first { it.binary == bitOf(changed.subList(0, 3)) }
    val bianUpper = Trigram.entries.first { it.binary == bitOf(changed.subList(3, 6)) }
    val huLower = Trigram.entries.first { it.binary == bitOf(lines.subList(1, 4)) } // 第2,3,4爻
    val huUpper = Trigram.entries.first { it.binary == bitOf(lines.subList(2, 5)) } // 第3,4,5爻
    val tiYong = when (tiYongRule) {
        TiYongRule.MOVING_LINE ->           // 通行规则：动爻所在之卦为用
            if (moving >= 4) TiYong(ti = lower, yong = upper)
            else             TiYong(ti = upper, yong = lower)
        TiYongRule.UPPER_YONG_LOWER_TI ->   // 笔记流派：上卦恒为用、下卦恒为体
            TiYong(ti = lower, yong = upper)
    }
    return ResolvedHexagram(upper, lower, moving, bianUpper, bianLower,
                            huUpper, huLower, tiYong)
}
```

> `TiYongRule` 取值 `MOVING_LINE`（默认）/ `UPPER_YONG_LOWER_TI`，由 DataStore 设置项 `ti_yong_rule` 提供（见 04 文档 §三）。

> 注意：全部取模计算使用 `Long`，防止用户输入大数（999,999,999 × 2 + 时数）溢出。

## 六、边界与规则裁定

实现中有争议的传统规则，本项目统一采用以下裁定，并在 UI 帮助文案中说明。

### 6.1 农历闰月与年界口径

| 项 | 裁定 |
| --- | --- |
| 闰月月份数 | 按本月份数计算（闰四月按 4），不加 0.5、不加 1 |
| 闰月实现约定 | 农历适配层返回的月份数**恒为正**；若某端实现用负数表示闰月（如 lunar-java 的 `getMonth()`），须在适配层或起卦入口取绝对值后再参与计算 |
| **年界口径** | 年数 Y 的「年」指**农历年**，以**正月初一**为年界（即 `lYear`），**不是**立春为界的干支纪年 |
| 年支与标签同源 | 起卦结果标签（如「乙巳年 腊月初三 午时」）的干支年**必须由同一个 `lYear` 派生**，不得改用农历库返回的 `gzYear`（立春口径）——两者每年在「正月初一 → 立春」之间约 13 天不一致，混用会出现「界面写丙午年、算法按巳=6 计算」的同一卦两个答案 |
| 备注 | 传统亦有「闰月取前月 + 半」等说法，本版不做配置项，帮助页说明口径。立春/正月初一两种年界在命理与易学中皆有流派使用，本版固定取**农历年**口径并保持两端一致 |

### 6.2 时辰划分与子时归属

| 项 | 裁定 |
| --- | --- |
| 时辰划分 | 23:00–00:59 子时、01:00–02:59 丑时……每两小时一时辰 |
| 晚子时（23:00 后） | 按**次日**的日数与子时（H=1）起卦（通行做法）；年支亦随次日切换 |
| 备注 | 「早晚子时」流派争议在帮助页说明，本版固定采用上述口径 |

### 6.3 数字 0 的处理

| 项 | 裁定 |
| --- | --- |
| 输入 0 | 第一版判定为无效输入，提示「请输入 1 以上的数字」。帮助页备注：部分流派将 0 按 10 处理，本版暂不支持 |

### 6.4 其他

| 项 | 裁定 |
| --- | --- |
| 笔画标准混用 | 同一次起卦内禁止混用；切换标准后输入框清空 |
| 查表缺失的汉字 | 不自动猜测，弹出对话框允许用户手动输入该字笔画数 |
| 手动输入时间 | 时间起卦页时间来源支持「当前时刻 / 公历 / 农历」（默认当前时刻）；手动输入提供公历 / 农历双页签：年份 1900–2100、时 0–23，农历含闰月开关。输入统一走 `castByTime`：公历先转农历，年支随输入年推导（农历年、以正月初一为界，见 §6.1）；23:00–01:00 晚子时仍按次日计（§6.2），位移口径不变 |

### 6.5 两字笔画起卦的秒钟数（v1.2 新增）

| 项 | 裁定 |
| --- | --- |
| 取值 | 起卦瞬间系统时间的秒位，0–59；在结果页「起卦上下文」中展示（如「… 14:32:06 · 秒 6」） |
| 参与方式 | 直接加和参与 mod 6；秒 = 0 时即不追加（0 视为有效值，不作无效处理） |
| 余 0 取 6 | 规则不变：(A+B+S) mod 6 = 0 时动爻取 6 |
| 作用范围 | **仅两字模式**。数字起卦不追加秒钟数（两数之和本身就是动爻口径，见 §2.2，已不含时辰项）。**一数 / 一字模式已于 v2.0 移除**（见 §2.2、§2.3 的「已移除」说明），秒数口径不再涉及它们。若后续变更，须同时改 03 §2.3、§6.5 与 07 TC-C03 |
| 复现性 | 秒数随起卦时刻变化，同一组字不同时刻动爻可不同；inputParams 必须记录 S 值，卦例详情据此完整复现 |
