### 2.2 实体：HexagramRecord（卦例记录）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | Long | PK, autoGenerate | 自增主键 |
| createdAt | Long | NOT NULL, 索引 | 起卦时间 epoch millis |
| method | String | NOT NULL | 起卦方式：TIME / NUMBER / CHARACTER / SOUND / RANDOM |
| inputParams | String | NOT NULL | 输入参数 JSON（见 §2.4） |
| lunarLabel | String | NOT NULL | 农历标签，如「丙午年 八月十五 午时」；非时间起卦存当前时刻农历 |
| upperTrigram | Int | NOT NULL | 上卦先天数 1–8 |
| lowerTrigram | Int | NOT NULL | 下卦先天数 1–8 |
| movingLine | Int | NOT NULL | 动爻 1–6 |
| benGuaCode | String | NOT NULL, 索引 | 本卦代码，统一为 `上卦数-下卦数`，如「06-05」（口径见 §2.5） |
| benGuaName | String | NOT NULL | 本卦卦名（冗余列，便于 SQL 关键字搜索，避免跨资产联查），如「水风井」 |
| huGuaCode | String | NOT NULL | 互卦代码 |
| bianGuaCode | String | NOT NULL | 变卦代码 |
| tiTrigram | Int | NOT NULL | 体卦先天数 |
| yongTrigram | Int | NOT NULL | 用卦先天数 |
| relation | String | NOT NULL | 体用关系：YONG_SHENG_TI / TI_SHENG_YONG / TI_KE_YONG / YONG_KE_TI / BI_HE |
| question | String? | 可空 | 所问之事（用户填写，≤200 字） |
| note | String? | 可空 | 备注（可后期编辑） |
| verifyStatus | String | NOT NULL, 索引, 默认 UNVERIFIED | 应验状态：UNVERIFIED（未验）/ VERIFIED（应验）/ PENDING（未验中）/ INVALID（不验） |
| updatedAt | Long | NOT NULL | 最近编辑时间 |

索引：`createdAt`（列表排序）、`benGuaCode`（按卦筛选）、`verifyStatus`（筛选）。

### 2.3 DAO 接口约定

```kotlin
@Dao
interface HexagramRecordDao {
    @Query("SELECT * FROM hexagram_record ORDER BY createdAt DESC")
    fun observeAll(): Flow<List<HexagramRecordEntity>>

    @Query("""SELECT * FROM hexagram_record WHERE
              question LIKE '%' || :kw || '%' OR
              note LIKE '%' || :kw || '%' OR
              benGuaName LIKE '%' || :kw || '%' ORDER BY createdAt DESC""")
    fun search(kw: String): Flow<List<HexagramRecordEntity>>

    @Insert suspend fun insert(r: HexagramRecordEntity): Long
    @Update suspend fun update(r: HexagramRecordEntity)
    @Query("DELETE FROM hexagram_record WHERE id = :id") suspend fun deleteById(id: Long)
}
```

> `search` 的卦名匹配依赖冗余列 `benGuaName`（见 §2.2 字段表），便于 SQL 搜索，避免跨资产联查。

### 2.4 inputParams JSON 结构

按起卦方式区分，统一存字符串字段：

```json
// TIME
{ "type": "TIME", "yearBranchNo": 7, "lunarMonth": 8, "lunarDay": 15, "hourNo": 7 }
// NUMBER（两数）
{ "type": "NUMBER", "mode": "TWO", "n1": 3, "n2": 8 }
// NUMBER（一数）
{ "type": "NUMBER", "mode": "ONE", "n1": 9, "hourNo": 7 }
// CHARACTER（两字；v1.2 起动爻含秒钟数，必须记录 second 保证复现）
{ "type": "CHARACTER", "mode": "TWO", "chars": ["梅", "花"], "strokes": [11, 8], "standard": "TRADITIONAL", "second": 6 }
// CHARACTER（一字；动爻由「笔画总数 + 时辰序数」决定，不加秒，必须记录 hourNo 保证复现）
{ "type": "CHARACTER", "mode": "ONE", "chars": ["梅"], "strokes": [11], "standard": "TRADITIONAL", "hourNo": 7 }
// SOUND
{ "type": "SOUND", "count1": 5, "count2": 3 }
```

### 2.5 卦代码口径

`benGuaCode` 统一为 `上卦数-下卦数`（如水风井 = `06-05`），卦名另存。互卦、变卦同理。先天数稳定，不依赖文字编码。

### 2.6 迁移策略

- 结构变更必须 `version + 1` 并编写 `Migration`，禁止 `fallbackToDestructiveMigration`。
- Schema JSON 提交到 git，PR 中出现 schema diff 时 reviewer 必须检查迁移脚本。

## 三、DataStore 设置项

| Key | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| stroke_standard | String | SIMPLIFIED | 简体 / 繁体笔画标准 |
| default_cast_method | String | TIME | 默认起卦方式 |
| ti_yong_rule | String | MOVING_LINE | 体用判定规则：MOVING_LINE（动爻所在为用，默认）/ UPPER_YONG_LOWER_TI（上卦恒为用、下卦恒为体，手写笔记流派，见 03 文档 §3.6、§八） |
| theme_mode | String | SYSTEM | LIGHT / DARK / SYSTEM |
| record_limit | Int | 0 | 0 = 不限制；否则超限后删除最旧 |
| disclaimer_acknowledged | Boolean | false | 首次启动声明页已确认 |

> 卦意关键词（hexagrams.json `keywords`）不落库，渲染时从知识库仓库按卦代码实时取用；卦例记录仅存卦代码，知识库词表更新后历史卦例自动获得新文案。

## 五、导出与备份

| 项 | 约定 |
| --- | --- |
| JSON 导出 | 全字段导出，含 schemaVersion: 1，数组按 createdAt 升序 |
| CSV 导出 | 列：时间、农历、方式、所问之事、本卦、互卦、变卦、动爻、体用、关系、备注、应验状态；UTF-8 with BOM（保证 Excel 打开不乱码） |
| 文件名 | guanmei_export_yyyyMMdd_HHmmss.json / .csv |
| 分享 | FileProvider + ACTION_SEND，写入 cache/share/ 临时目录 |
| 未来备份 | 预留「导出全部数据 / 导入」功能（P2），导入时按 schemaVersion 校验 |

## 六、数据安全与清理

| 项 | 约定 |
| --- | --- |
| 加密 | 卦例为非敏感内容，不加密；如用户填写敏感所问之事，说明文案提示「数据仅存本机」 |
| 卸载行为 | 数据随应用卸载删除（无外部存储残留），在隐私说明中写明 |
| record_limit | 设置非 0 上限时，插入后异步清理最旧记录至限额 |
