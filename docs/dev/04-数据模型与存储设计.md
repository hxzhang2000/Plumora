## 一、存储总览

两端**字段契约与设置项完全一致**，仅承载介质不同：

| 用途 | Android 端（后续阶段） | Web 端（当前阶段） | 说明 |
| --- | --- | --- | --- |
| 卦例记录 | Room（SQLite） | IndexedDB | 唯一的用户数据落盘位置 |
| 应用设置 | DataStore (Preferences) | localStorage | 笔画标准、默认起卦方式、主题等 |
| 卦象知识库 | assets/knowledge/*.json | packages/knowledge 编译进产物 | 只读，随应用打包 |
| 导出文件 | files/export/ | 浏览器下载目录 | JSON/CSV 临时产物 |

**不接入云同步、不发任何网络请求。**用户数据 100% 本地（Web 端为纯静态站点，无后端接口）。

## 二、卦例记录存储

### 2.1 存储配置

| 项 | Android 端（Room） | Web 端（IndexedDB） |
| --- | --- | --- |
| 名称 | guanmei.db | plumora |
| 版本 | 1 | 1 |
| 结构导出 | 开启（`room.schemaLocation` → `app/schemas/`，纳入版本控制） | 无 schema 文件，结构以本文件 §2.2 为准 |
| 对象仓库 / 表 | hexagram_record | hexagram_record |
| 主键 | id（Long, autoGenerate） | id（keyPath，autoIncrement） |

### 2.2 实体：HexagramRecord（卦例记录）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | Long | PK, autoGenerate | 自增主键 |
| createdAt | Long | NOT NULL, 索引 | 起卦时间 epoch millis |
| method | String | NOT NULL | 起卦方式：TIME / NUMBER / CHARACTER / RANDOM（旧值 `SOUND` 只读保留，见 §2.4） |
| inputParams | String | NOT NULL | 输入参数 JSON（见 §2.4） |
| lunarLabel | String | NOT NULL | 农历标签，如「丙午年 八月十五 午时」；非时间起卦存当前时刻农历 |
| upperTrigram | Int | NOT NULL | 上卦先天数 1–8 |
| lowerTrigram | Int | NOT NULL | 下卦先天数 1–8 |
| movingLine | Int | NOT NULL | 动爻 1–6 |
| benGuaCode | String | NOT NULL, 索引 | 本卦代码，统一为 `上卦数-下卦数`，如「06-05」（口径见 §2.5） |
| benGuaName | String | NOT NULL | 本卦卦名（冗余列，便于关键字搜索，避免跨资产联查），如「水风井」 |
| huGuaCode | String | NOT NULL | 互卦代码 |
| bianGuaCode | String | NOT NULL | 变卦代码 |
| tiTrigram | Int | NOT NULL | 体卦先天数（按**起卦当时生效的流派**判定后落库） |
| yongTrigram | Int | NOT NULL | 用卦先天数（同上） |
| tiYongRule | String | NOT NULL | 起卦当时生效的体用判定流派：MOVING_LINE / UPPER_YONG_LOWER_TI。**必须落库**——记录只存 tiTrigram/yongTrigram，若不存流派，日后用户切换设置后无法说明该卦例的体用是按哪个口径算的（见 §2.7） |
| relation | String | NOT NULL | 体用关系：YONG_SHENG_TI / TI_SHENG_YONG / TI_KE_YONG / YONG_KE_TI / BI_HE |
| question | String? | 可空 | 所问之事（用户填写，≤200 字）；**同时是记录名称的首选来源**，见 §2.8 |
| note | String? | 可空 | 备注（可后期编辑） |
| verifyStatus | String | NOT NULL, 索引, 默认 UNVERIFIED | 应验状态：UNVERIFIED（未验）/ VERIFIED（应验）/ PENDING（未验中）/ INVALID（不验） |
| updatedAt | Long | NOT NULL | 最近编辑时间 |

索引：`createdAt`（列表排序）、`benGuaCode`（按卦筛选）、`verifyStatus`（筛选）。

### 2.3 仓储接口约定

Android 端（Room DAO）：

```kotlin
@Dao
interface HexagramRecordDao {
    @Query("SELECT * FROM hexagram_record ORDER BY createdAt DESC")
    fun observeAll(): Flow<List<HexagramRecordEntity>>

    @Query("""SELECT * FROM hexagram_record WHERE
              question LIKE '%' || :kw || '%' OR
              note LIKE '%' || :kw || '%' OR
              benGuaName LIKE '%' || :kw || '%' ORDER BY createdAt DESC""")
    fun search(kw: String): Flow<List<HexagramRecordEntity>>

    @Insert suspend fun insert(r: HexagramRecordEntity): Long
    @Update suspend fun update(r: HexagramRecordEntity)
    @Query("DELETE FROM hexagram_record WHERE id = :id") suspend fun deleteById(id: Long)
}
```

Web 端（IndexedDB，见 `apps/web/src/platform/records.ts`）：

| DAO 能力 | Web 端对应实现 |
| --- | --- |
| `observeAll()` | `listRecords()` —— `getAll()` 后按 `createdAt` 倒序；视图用 `onActivated` 主动重查（无 Flow，改为拉取） |
| `search(kw)` | `queryRecords({ keyword })` —— 同一套三列匹配（question / note / benGuaName），大小写不敏感 |
| `insert` / `update` / `deleteById` | `insertRecord` / `updateRecord` / `deleteRecord` |
| 索引 | `createIndex('createdAt' \| 'benGuaCode' \| 'verifyStatus')` |

> 两端的关键字匹配必须命中**同样三列**（所问之事 / 备注 / 本卦卦名）；Web 端的卦名匹配同样依赖冗余列 `benGuaName`（见 §2.2 字段表）。

### 2.4 inputParams JSON 结构

按起卦方式区分，统一存字符串字段：

```json
// TIME（shifted = 是否晚子时：23:00 后按次日计，03 §6.2）
// 必须记录 shifted：晚子时与「次日 00:30」的四个数值完全相同，不存标记则详情页无法说明该卦是按次日算的
{ "type": "TIME", "yearBranchNo": 7, "lunarMonth": 8, "lunarDay": 15, "hourNo": 7, "shifted": false }
// TIME（晚子时：2026-09-25 23:30 → 按八月十六 子时计）
{ "type": "TIME", "yearBranchNo": 7, "lunarMonth": 8, "lunarDay": 16, "hourNo": 1, "shifted": true }
// NUMBER（两数）
{ "type": "NUMBER", "mode": "TWO", "n1": 3, "n2": 8 }
// NUMBER（一数；已移除，旧数据兼容保留）
{ "type": "NUMBER", "mode": "ONE", "n1": 9, "hourNo": 7 }
// CHARACTER（两字；v1.2 起动爻含秒钟数，必须记录 second 保证复现）
{ "type": "CHARACTER", "mode": "TWO", "chars": ["梅", "花"], "strokes": [11, 8], "standard": "TRADITIONAL", "second": 6 }
// CHARACTER（一字；已移除，旧数据兼容保留——动爻由「笔画总数 + 时辰序数」决定，不加秒，hourNo 保证复现）
{ "type": "CHARACTER", "mode": "ONE", "chars": ["梅"], "strokes": [11], "standard": "TRADITIONAL", "hourNo": 7 }
```

> **已移除，旧数据兼容保留：`mode='ONE'`（一数 / 一字模式）**（v2.0 产品决策）。
> 起卦入口已不再产生这两种 inputParams——数字起卦仅两数、汉字起卦仅两字
> （03 文档 §2.2、§2.3）；上面两行示例**只为读取历史卦例保留**，字段结构不迁移、
> 不回写（§2.6 禁止 destructive migration）。详情页据 `hourNo` 原样复现当年的动爻；
> `mode='TWO'` 为当前唯一在用形态。

> **已下线：`SOUND`（声音 / 点数起卦）**。新记录不再产生该 type；库里已有的旧记录
> **只读保留、不做迁移回写**（§2.6 禁止 destructive migration，且回写成哪种方式都等于
> 篡改历史）。展示层一律走 `methodCn()` 容错：未知 / 已下线的方式回退为「其他方式」，
> 不得渲染出 `undefined`；派生名称（`recordTitle()`）则**不给方式片段**，继续回退到
> 卦名 / 固定兜底串。

### 2.5 卦代码口径

`benGuaCode` / `huGuaCode` / `bianGuaCode` 统一为 `上卦数-下卦数`，**两段各固定两位、不足补零**：

- 水风井（坎上巽下）= `06-05`；乾为天 = `01-01`；坤为地 = `08-08`
- 固定宽度使该列**按字典序排序等价于按数值序排序**，可直接作为索引键与导出文件名使用
- 卦名另存（`benGuaName`），代码不依赖文字编码，两端（Web / Android）共用同一生成规则

> 读取历史数据时须兼容非补零写法（`6-5` 等价 `06-05`）：知识库的 `getHexagramByCode()` 已做归一。

### 2.6 迁移策略

- 结构变更必须 `version + 1` 并编写迁移，禁止删库重建（Android 端禁止 `fallbackToDestructiveMigration`；Web 端禁止在 `onupgradeneeded` 里 drop 对象仓库）。
- Android 端 Schema JSON 提交到 git，PR 中出现 schema diff 时 reviewer 必须检查迁移脚本。

### 2.7 体用流派与历史卦例的一致性

| 场景 | 行为 |
| --- | --- |
| 起卦时 | 按当前设置 `ti_yong_rule` 判定体用，并把 `tiTrigram` / `yongTrigram` / `tiYongRule` 三列一并落库 |
| 回放历史卦例 | **以落库的 `tiTrigram` / `yongTrigram` 为准**，不按当前设置重算——否则用户切换流派后，历史卦例的体用会被悄悄改写 |
| 仅暂存未落库的排盘 | 按当前设置重算（暂存只存「起卦输入 + 生效流派」，见 02 文档 §5.3） |

### 2.8 记录名称（派生字段，不落库）

列表主标题、详情页标题与删除确认文案统一取**同一条名称规则**（实现在 `@plumora/core` 的 `recordTitle()`，两端共用，勿各写一份）：

| 优先级 | 取值 | 说明 |
| --- | --- | --- |
| ① | `question`（trim 后非空） | **所问之事，即占卜目标**——填了目标就用目标当名称 |
| ② | `benGuaName` | 未填目标时回退到本卦卦名（冗余列，正常数据必有值） |
| ③ | `起卦方式 · lunarLabel` | 卦名也缺失时的兜底，避免出现空白标题 |
| ④ | `未命名卦例` | 数据整体异常时的最后兜底 |

**为什么是派生值而不是表字段**：名称完全由 ① / ② 决定。若落库成列，用户在详情页改完「所问之事」后名称列就与被改的字段脱钩，还得靠迁移去修数据（违反 §2.6 禁止 destructive migration）。派生值天然与被改字段同步，两端也只需维护一份规则。

## 三、设置项

两端 Key 与默认值完全一致：

| Key（Android） | Key（Web，localStorage） | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| stroke_standard | strokeStandard | String | SIMPLIFIED | 简体 / 繁体笔画标准 |
| default_cast_method | defaultCastMethod | String | TIME | 默认起卦方式 |
| ti_yong_rule | tiYongRule | String | MOVING_LINE | 体用判定规则：MOVING_LINE（动爻所在为用，默认）/ UPPER_YONG_LOWER_TI（上卦恒为用、下卦恒为体，手写笔记流派，见 03 文档 §3.6、§八） |
| theme_mode | theme | String | SYSTEM | LIGHT / DARK / SYSTEM |
| record_limit | recordLimit | Int | 0 | 0 = 不限制；否则超限后删除最旧 |
| disclaimer_acknowledged | disclaimerAcknowledged | Boolean | false | 首次启动声明页已确认 |

> Web 端整体存为**单个 JSON 对象**于 localStorage 键 `plumora.settings.v1`（而非 6 个独立键）；读取时与默认值合并，缺失字段自动补齐、脏数据回退默认值。这是承载方式差异，不影响设置项的语义契约。

> 卦意关键词（hexagrams.json `keywords`）不落库，渲染时从知识库按卦代码实时取用；卦例记录仅存卦代码，知识库词表更新后历史卦例自动获得新文案。

## 六、数据安全与清理

| 项 | 约定 |
| --- | --- |
| 加密 | 卦例为非敏感内容，不加密；如用户填写敏感所问之事，说明文案提示「数据仅存本机」 |
| 卸载行为 | Android 端数据随应用卸载删除（无外部存储残留）；Web 端数据存于浏览器 IndexedDB / localStorage，清除站点数据即删除。均需在隐私说明中写明 |
| record_limit | 设置非 0 上限时，插入后异步清理最旧记录至限额 |
