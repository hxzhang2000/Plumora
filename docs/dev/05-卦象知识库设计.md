## 三、六十四卦数据（hexagrams.json）

### 3.1 JSON Schema

```json
{
  "code": "06-05",
  "upper": 6,
  "lower": 5,
  "name": "水风井",
  "shortName": "井",
  "binary": 22,
  "keywords": ["水牛", "贤德"],
  "guaci": "井：改邑不改井，无丧无得，往来井井。汔至亦未繘井，羸其瓶，凶。",
  "lines": [
    { "index": 1, "name": "初六", "text": "井泥不食，旧井无禽。" },
    { "index": 2, "name": "九二", "text": "井谷射鲋，瓮敝漏。" },
    { "index": 3, "name": "九三", "text": "井渫不食，为我心恻，可用汲。王明，并受其福。" },
    { "index": 4, "name": "六四", "text": "井甃，无咎。" },
    { "index": 5, "name": "九五", "text": "井洌，寒泉食。" },
    { "index": 6, "name": "上六", "text": "井收勿幕，有孚元吉。" }
  ],
  "yongText": null
}
```

| 字段 | 说明 |
| --- | --- |
| code | 上卦数-下卦数，**两段各两位、不足补零**（如 `06-05`），与 04 §2.5 的数据库口径一致 |
| binary | 六爻位编码（下爻 bit0）：**下卦 binary 按位或（上卦 binary 左移 3 位）**，即 §3.4 校验规则 3 的公式。水风井 = 巽(6) 按位或 坎(2)<<3 = **22**（注意：**不是**周易卦序 48） |
| keywords | 卦意关键词数组（1–5 个），来源为手写笔记口径，见 §3.5 完整词表 |
| guaci | 卦辞全文（含「XX：」前缀） |
| lines | 六爻，index 1–6，name 按 §3.5 爻名规则（见 03 文档） |
| yongText | 仅乾、坤二卦有值（「用九」「用六」），其余为 null；存在时不并入 `lines`，保持 `lines` 恒为 6 条 |

### 3.3 内容录入计划

| 阶段 | 内容 | 数量 |
| --- | --- | --- |
| M1（MVP） | 64 卦卦名 + 卦符 + 上下卦组合 + **卦意关键词（keywords，手写笔记口径已定稿）**；**动爻爻辞**（386 条：384 爻辞 + 用九 + 用六）；卦辞全文 | 一次录入 |
| M2 | 卦名含义简注、白话参考 | 64 + 386 |
| M3 | 彖传 / 象传（可选） | 64 + 386 |

> MVP 阶段 UI 仅展示「本卦卦辞 + 动爻爻辞」，其余阶段内容不展示，避免知识库不完整导致 UI 缺字。

### 3.4 校验规则（加载时）

1. hexagrams.json 必须恰好 64 条，code 无重复，覆盖 3.2 表全部组合。
2. 每卦 `lines` 必须恰 6 条。乾、坤二卦的「用九」「用六」不并入 `lines`，单独存于 `yongText` 字段（其余卦为 null）——保证 `lines` 长度恒为 6，简化校验与遍历。
3. binary 与 upper/lower 编码一致性校验（`binary == lower.binary | upper.binary << 3`）。
4. 每卦 `keywords` 必须非空，条数 **1–5 个**，与 §3.5 人工校对后词表一致。
   > 下限为 1 而非 2：手写笔记中「水火既济」原文仅记一词（「已经完成」），校对后仍为 1 条。为忠实保留笔记原貌，规则下限放宽至 1，**不对该卦补词**（补词属内容创作，非校对）。
5. 任一校验失败：Debug 构建直接抛异常；Release 构建降级为「卦名 + 空文本」并记录本地日志。

## 四、笔画映射数据（strokes_*.json）

### 4.1 JSON 结构

```json
{
  "standard": "TRADITIONAL",
  "version": 1,
  "strokes": {
    "梅": 11,
    "花": 8,
    "觀": 25,
    "观": 6
  }
}
```

**表键与查表口径**（`packages/knowledge/src/strokes.ts` 的实现约定）：

| 项 | 约定 |
| --- | --- |
| 录入表键 | 一律为**简体字面**；繁体笔画由 `t` 字段承载（`{ s: 6, t: 25 }`），缺省视为与简体相同 |
| 繁体字面输入 | 经**繁体→简体别名表**（`TRADITIONAL_ALIAS`，如 `觀 → 观`）归一后取值，**不重复录入笔画数值** |
| 查表结果 | `lookupStrokes('觀', 'TRADITIONAL') = 25`、`lookupStrokes('觀', 'SIMPLIFIED') = 6`，与 `lookupStrokes('观', …)` 对称——**标准决定按哪个字形计画**，输入字面不决定 |
| 导出 JSON | 上面示例的扁平 `字 → 笔画数` 是**按 standard 展开后的导出形态**（`standard: TRADITIONAL` 时繁体字面与简体字面各按其字形给值），不是内部录入表 |

> 之所以用别名表而非在录入表里并列 `观` / `觀` 两个键：同一笔画数值若在仓库里出现两份，必然改一处漏一处。

### 4.2 录入与校验

| 项 | 约定 |
| --- | --- |
| 收字范围 | 通用规范汉字表一级 3500 字 + 常用二级 4500 字；繁体按传统辞书笔画口径 |
| 校验 | 抽样 100 字与《新华字典》笔画附录人工比对；金标准字对：梅=11（繁）、花=8（繁） |
| 缺字处理 | 运行时查表 miss → 弹窗让用户手动输入笔画数，并支持「记住该字」写入 DataStore 本地补充表 |
| 免责 | 帮助页注明「笔画数以本应用内置标准为准，不同辞书或有出入」 |
