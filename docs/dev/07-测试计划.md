## 一、测试范围与策略

两端共用同一套「共享层」测试，平台层各自补测：

| 层级 | 范围 | 工具 | 覆盖目标 |
| --- | --- | --- | --- |
| 共享层单元测试 | 起卦算法、卦象推导、五行生克、笔画查询、知识库校验 | Vitest（Web）/ JUnit5（Android） | 语句覆盖 ≥ 95% |
| 农历封装测试 | 公历 ↔ 农历、晚子时、时辰边界、年界口径 | Vitest / JUnit5 | 金标准日期 + **全范围逐日穷举**（1900–2100 共 73,384 天）不变量与往返一致性 |
| 数据库测试 | 记录增删改查、关键字搜索、迁移 | Vitest（IndexedDB）/ Robolectric（Room） | 关键路径全覆盖 |
| 应用层测试 | 路由解析、设置读写、导出纯函数、排盘暂存 | Vitest（Web）/ JUnit5（Android） | 冒烟主流程 |
| 运行时冒烟 | 组件挂载、逐路由渲染、控制台零错误 | jsdom（Web，`npm run test:runtime`）/ Compose UI Test | 抓「挂载即白屏」类缺陷 |
| 版本一致性 | 派生版本号与真源逐字节比对、CHANGELOG 条目存在性 | `npm run version:check`（Web + Android 共用） | 抓版本静默分叉 |
| UI 测试 | 起卦主流程、保存卦例、设置切换 | 手工走查为主（Web）/ Compose UI Test（Android） | 冒烟主流程 |
| 手工测试 | 兼容性、真机 / 真浏览器验证、视觉走查 | 手动 | 每轮发布前 |

> **为什么单测之外还需要运行时冒烟**：Vitest 单测跑在 `environment: node` 下，只覆盖纯逻辑；`vue-tsc` 只做类型检查。两者都发现不了「组件挂载时抛错导致整页白屏」。故 Web 端额外把应用打成单文件 IIFE，在 jsdom 里真实执行一遍（见 §3.9）。

> **共享层的断言集必须两端一致**：同一份用例号（TC-*）在 Web 与 Android 两侧都要有对应测试，任一端不通过即为 S0。当前 Web 端已落地的对拍脚本与用例见 §3.8、§3.9。

## 二、金标准算例（必须最先通过的用例）

### 2.1 算例 A：时间起卦

| 项 | 值 |
| --- | --- |
| 输入 | 农历 2026 年（丙午，年支午=7）八月十五日 午时（H=7） |
| 中间量 | S1 = 30，S2 = 37 |
| 上卦 | 30 mod 8 = 6 → 坎 |
| 下卦 | 37 mod 8 = 5 → 巽 |
| 动爻 | 37 mod 6 = 1 → 初爻 |
| 本卦 | 水风井（坎上巽下） |
| 变卦 | 水天需（坎上乾下） |
| 互卦 | 火泽睽（本卦六爻自下而上 = 巽[0,1,1] + 坎[0,1,0] = [0,1,1,0,1,0]；第 2,3,4 爻 [1,1,0] = 兑（互下卦）、第 3,4,5 爻 [1,0,1] = 离（互上卦）→ 离上兑下 = 火泽睽。**v1.4 更正**：泽火革为兑上离下，与「二三四爻为互下卦」规则不符；通行口径经「既济互未济」验证） |
| 体用 | 体坎（水）、用巽（木） |
| 生克 | 坎水生巽木 → 体生用 → 小凶 |

> 注：算例 A 的互卦以程序推导结果为准，录入测试断言前先用 03 文档 §3.4 规则手工推演一遍并双人核对，避免「拿结果凑结果」。

### 2.2 算例 B：汉字笔画起卦

| 项 | 值 |
| --- | --- |
| 输入 | 「梅」（繁体 11 画）、「花」（繁体 8 画），起卦时刻秒钟数 S=6 |
| 上卦 | 11 mod 8 = 3 → 离 |
| 下卦 | 8 mod 8 = 0 → 取 8 → 坤 |
| 动爻 | (11 + 8 + 6) = 25 mod 6 = 1 → 初爻 |
| 本卦 | 火地晋（离上坤下） |
| 变卦 | 火雷噬嗑（离上震下） |
| 互卦 | 水山蹇（坎上艮下；v1.4 更正，见 03 文档 §3.4 口径更正） |
| 体用 | 体离（火）、用坤（土） |
| 生克 | 体生用（火生土）→ 小凶 |

### 3.9 Web 端运行时冒烟（WebRuntimeSmoke）

落在 `apps/web/scripts/runtime-smoke.cjs`（配置 `apps/web/vite.smoke.config.ts`，命令 `npm run test:runtime`，共 **10 条**）。
做法：把应用打成单文件 IIFE → 在 jsdom 中执行 → 逐路由断言渲染文案 + 断言零运行时错误。
jsdom **不实现 IndexedDB**，故脚本挂了一个最小替身 `apps/web/scripts/idb-stub.cjs`，好让「保存卦例 → 列表」这条链路真的跑起来。

| 用例号 | 场景 | 期望 |
| --- | --- | --- |
| TC-WR01 | 应用挂载 | `#app` 有子节点，DOM 非空，`console.error` / `window.error` / `unhandledrejection` 均为 0 |
| TC-WR02 | `#/cast` 渲染 | 含「起卦」与当前农历标签 |
| TC-WR03 | `#/result` 渲染（预置算例 A） | 含 水风井 / 水天需 / 火泽睽 / 体生用 / 小凶 / 体坎 / 用巽 |
| TC-WR04 | `#/records` 渲染 | 含「卦例」；**空态走本路由特有文案**「还没有卦例」（原断言只查「卦例」二字，空态与列表态都会命中，等于没验证路由真的渲染了） |
| TC-WR05 | `#/learn` 渲染 | 含「八卦类象」「六十四卦」 |
| TC-WR06 | 打开设置面板「关于」区 | 显示的版本号与 `version.json` 真源一致（验证生成常量真的接到了 UI） |
| TC-WR07 | 品牌图标接线 | 页头/侧栏有 `icon.svg`、关于区有 `mark.svg`，且**引用的文件必须真实存在于 `public/`**（防线上 404） |
| TC-WR08 | 卦例名称端到端（TC-D08/D09 的界面口径） | 结果页填「所问之事」→ 保存 → 列表标题即该目标；不填目标再存一条 → 标题回退到卦名；标题已是卦名时副行不重复卦名 |
| TC-WR09 | **弹窗残留（W-1/W-2）** | 正向对照：详情页打开删除确认弹窗后 DOM 中确有弹窗、`body` 滚动被锁 → 切到列表页后**弹窗不得残留**、滚动必须解锁、此时按 Enter **不得误删**（断言 `idb.size()` 不变）。复现的是 KeepAlive 缓存下 `open` 状态未复位 |
| TC-WR10 | **设置抽屉无障碍（W-7）** | 抽屉关闭时 `aside` 必须带 `inert` + `aria-hidden="true"`（否则 Tab 会把焦点走进看不见的面板） |

> 不覆盖真实布局与视觉（jsdom 无排版引擎），那部分靠 §4.1 的手工走查。冒烟脚本仅用于抓「挂载即白屏」这类单测与类型检查都漏掉的缺陷。

> **替身自检**：`IDB_STUB_SELFTEST=1 node apps/web/scripts/runtime-smoke.cjs` 会让替身故意不落库，此时 TC-WR08 必须 FAIL 且退出码为 1——用于证明这条断言不是空转（永远通过的护栏等于没有护栏）。同理，TC-WR09 是临时注释掉 `onDeactivated` 复位后冒烟精确报出的缺陷。
>
> **替身的调度器可注入**：默认 `setTimeout(fn, 0)`（贴近浏览器「回调落在后续任务」），但 **Windows 上 `setTimeout(0)` 的实际粒度约 15.6ms**，逐条插 501 条数据会要 7 秒以上。`apps/web/test/records.test.ts` 因此传 `scheduler: queueMicrotask`——「回调仍在赋值之后触发」这一契约不变，耗时降到毫秒级。

### 3.10 版本一致性（VersionConsistencyCheck）

落在 `scripts/version.mjs` 的 `check` 子命令（`npm run version:check`，已置于 `npm run verify` 第一步）。
做法：对每个派生目标用**与 `sync` 相同的渲染函数**重算期望内容，与磁盘逐字节比对。

| 用例号 | 场景 | 期望 |
| --- | --- | --- |
| TC-V01 | 全部派生目标与真源一致 | 退出码 0 |
| TC-V02 | 手工改动任一 `package.json` 的 version | 退出码 1，指名报出该文件 |
| TC-V03 | 手工改动 `apps/web/src/generated/version.ts` | 退出码 1 |
| TC-V04 | 真源已升版本但未跑 `sync` | 退出码 1，列出全部落后目标 |
| TC-V05 | CHANGELOG.md 缺当前版本条目 | 退出码 1，提示「缺少 vX.Y.Z 的条目」 |
| TC-V06 | 真源 version 非 `X.Y.Z` 形态 | 退出码 1，提示版本形态错误 |
| TC-V07 | minor 或 patch ≥ 100（versionCode 会碰撞） | 退出码 1，拒绝并说明原因 |
| TC-V08 | `apps/android/` 不存在 | 跳过 Android 目标且不报错（标注「未启用」） |

> **为什么必须验证「校验器本身会失败」**：一个永远通过的校验脚本与没有校验等价。TC-V02~V07 已用注入漂移的方式实测过，确认退出码与报错信息都正确。
