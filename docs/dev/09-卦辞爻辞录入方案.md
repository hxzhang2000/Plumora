## 二、源材料选定：zy.pdf 方案的证伪与替代

### 2.1 原方案前提的证伪

v1.x 选定 `zy.pdf` 为底稿，理由是「文本层完全可提取、已是简体、结构标记清晰」。但 §4.3 的井卦金标准抽检（当时即已完成）推翻了这个前提：

| 位置 | `zy.pdf` | 通行本（05 §3.1） |
| --- | --- | --- |
| 井·卦辞 | 汔至，亦未**□**井 | 汔至亦未**繘**井 |
| 井·九三 | 为我**民**恻 | 为我**心**恻 |
| 井·九五 | 井**冽** | 井**洌** |
| 井·上六 | 有孚**无**吉 | 有孚**元**吉 |

仅一卦即 4 处异文 / 缺字 / 错字。**抽检一卦的失真密度意味着全量 64 卦不可信**——若以 `zy.pdf` 为底稿，450 条文本将携带不可预估的错误，人工校对无法在合理成本内发现（因为校对者无独立基准可对照）。故 `zy.pdf` 不能作为权威源，只能作为**对拍见证**（与另一独立源交叉比对时提供第三方意见）。

### 2.2 新权威源：维基文库《周易正義》

## 三、抓取与结构化

### 3.1 抓取通道

本地直连 `zh.wikisource.org` 全部 TCP reset（错误码 10054），不可用。改用 **anysearch extract 服务端抓取**（`anysearch` skill 的 CLI，服务端代抓后返回 Markdown），64 页全部成功。

抓取产物不入库（维基文库转写层为 CC-BY-SA，且体积远大于所需），**仅从中提取公有领域经文**，底库以独立文件形式归档（§5.2）。

### 3.2 页面 URL 真源：索引页 `idx.bin`

⚠️ **slug 用字坑（3 例实测，代价：3 次失败抓取 + 1 轮误判）**：

| 卷 | 索引页显示的卷名 | 真实页面 slug | 易误用（失败） |
| --- | --- | --- | --- |
| 卷一 | 上经**干**传卷一（维基文库自身错字） | `01乾`（U+4E95） | `01干`（U+5E72） |
| 卷四 | 下经咸传卷四 | `04恒`（**U+6052**） | `04恆`（U+6056） |
| 卷四 | 同上 | `04遁`（**U+906F**） | `04遯`（U+9041） |

**教训**：slug 一律从索引页抓取件的 URL 链接中解析取真值，**不手维护清单、不由目视繁简判断**。同一卷内「卷名用字」「链接用字」「页面正文用字」三者可能各不相同（卷四链接用 `恒`，而该页正文卦名写作 `恆`）。

⚠️ **诊断线索**：slug 用字错误与 transient 服务故障**报错完全相同**（`API Error: Unable to extract content from the URL`）。同一 URL 重试 2 次仍报此错，应判定为用字错，**立即查索引页，不要继续重试**（重试只会烧时间）。

### 3.3 页面结构与解析状态机

单卦页面结构（64 页实测）：untrusted 提示头 → `## {标题} - 維基文庫` → `**Source**` → `---` 分隔线 → 站点导航 → `[周易]第N卦` → `## {卦名}…` → 经文 / 注疏交错 → 页脚 `取自「…oldid=N`。

正文起始须切到 `---` 分隔线之后，否则会把标题行的伪 `## ` 当成本文标题。

解析用 5 态状态机，**爻辞 / 用九只在 `guaci / yao / xiang` 态接受**：

| 态 | 入口 | 语义 | 是否采集 |
| --- | --- | --- | --- |
| `guaci` | 页首 | 卦象前缀 + 卦辞 | ✅ |
| `yao` | 首个爻名行 | 爻辞 / 用九用六 | ✅ |
| `tuan` | `《彖》` / `彖曰` | 彖传 | ❌ 整段跳过 |
| `xiang` | `《象》` / `象曰` | 大象 + 六条小象 | ❌ 跳过（遇爻名行回 `yao`） |
| `wenyan` | `《文言》` / `文言` | 文言（仅乾坤） | ❌ 整段跳过 |

注疏截断标记（出现即截断该行至标记前）：`【【疏】`、`【疏】`、`[疏]`、`正義曰`、`○注`。注意 `[疏]` **可出现在行中**，须行内截断而非按行丢弃。

### 3.4 卦辞提取法：剥卦象前缀（取代「卦名锚点」法）

前缀正则 `^[乾坤震巽坎離艮兌]下[乾坤震巽坎離艮兌]上[。．]?\s*` —— **64 页 100% 命中**，剥除后余下即卦辞。

旧方案「以『卦名：』为锚点切分」在 4 类页面**全部失效**：

| 卦 | 形态 | 锚点法为何失效 |
| --- | --- | --- |
| 03 坎 | `習坎：` | 卦名为 2 字「習坎」，非「坎」 |
| 02 同人 | `同人於野，亨…` | 无「卦名：」锚点，卦名自然嵌句首 |
| 02 否 | `否之匪人，不利君子貞…` | 同上 |
| 01 乾 | `〈乾：元、亨、利、貞。〉` | 整段被〈〉包裹，锚点在注记壳内（全库唯一） |

故改用「剥前缀」法：先剥卦象，再判全串是否被〈〉整体包裹（`^〈(.+)〉$` 则解包），再剥内嵌〈注〉。同人 / 否**不补「卦名：」锚点**（卦名已自然嵌于句首，补则重复）。

### 3.6 数据存储架构与内容规范

#### 3.6.1 四层数据存储体系

数据从维基文库源站到运行时代码，经历四层存储，每层有明确的用途与生命周期：

| 层级 | 名称 | 路径 | 格式 | 生命周期 | 入库 |
| --- | --- | --- | --- | --- | --- |
| L1 | 抓取件（原始文本） | `zys/pages/`（zh-hant 权威层，64 卦）、`zys/pages_hans/`（zh-hans 交付层，64 卦）、`zys/pages_10/`（十翼 zh-hant，34 页）、`zys/pages_hans_10/`（十翼 zh-hans，34 页） | Markdown（anysearch 服务端抓取件） | 临时工作区，随会话保留 | ❌ 不入库 |
| L2 | 结构化数据 | `zys/parsed.json`、`zys/parsed_hans.json` | JSON（解析器 v4 产出） | 临时工作区 | ❌ 不入库 |
| L3 | 底稿 / 备存册 | `docs/dev/knowledge-review/周易原文转写底稿.md`（450 条主底库）、`docs/dev/knowledge-review/周易三传备存.md`（彖/大象/小象/文言） | Markdown（含逐条留痕、存疑标记、校对栏） | 永久归档 | ✅ 入库（文档层） |
| L4 | 入库目标 | `packages/knowledge/src/hexagrams.ts` 的 `RAW` 表 | TypeScript 源码 | 永久（CI 门禁） | ✅ 入库（代码层） |

**十翼数据**（v2.2 新增 / v2.3 设计文档完成）：L1 层新增 `pages_10/` 与 `pages_hans_10/` 各 34 页，共约 281 KB。十翼原文暂不入库（L4），仅作 L1 层存档备未来使用。存储结构设计已定稿（`knowledge-review/design/十翼原文展示-UI设计规格.md` v0.2 §8：`shiYi.ts` + `shiYi.generated.ts`，作为现有知识库第 4 个数据集与 `hexagrams.ts` 平行，纯数据零依赖、`readonly` 契约、繁体权威 + 简体交付、稳定 chapter ID），尚未实施。

| | `wenyan` | `readonly string[]?` | 仅乾、坤；按段渲染（每段自带「初九曰：」等前缀） | ✅ 已入库 |

**M3 传注层设计要点**：
- 全部 optional（`?`），底库未录时字段缺失（`undefined`），不影响 `build()` 与 `validate()`；
- UI 依「字段非 undefined 即显示，否则整卡隐藏」的降级路径渲染（设计规格 §5.4）；
- `xiaoxiang` 以爻名为键（非 index），与 `lines[i].name` 对应，便于逐爻取键；
- `wenyan` 用 `string[]` 而非单一字符串：合并会脆弱依赖标点（§4.5 第 7 项裁定）。

#### 3.6.4 UI 展示架构

「卦级原文聚合展示」组件（`GuaciYaoCiPanel.vue`）数据流：

```
Hexagram 对象（含 guaci / lines / yongText / tuan / daxiang / xiaoxiang / wenyan）
  → 主区（永远展开）：卦辞卡 + 爻辞卡（6 行合一，含动爻三重信号 + 小象）+ 用九/用六卡
  → 次区（手风琴，默认折叠）：彖 + 大象 + 文言（按段）
  → 空态规则：字段 null/undefined → 整卡不渲染；主区全无数据 → 整分区不渲染
```

**数据降级路径**：M1 文本层（`guaci / lines / yongText`）为 `null` 时，主区无数据，组件不渲染；M3 传注层（`tuan / daxiang / wenyan`）为 `undefined` 时，次区手风琴不显示。数据入库后组件自动激活，无需二次改代码。

### 4.6 注泄漏排查（正则盲区）

第 13 项是正则**原理性无法识别**的：注若无〈〉包裹，与经文在字符层面完全无别。故另建启发式检测——注文有强特征虚词，经文中几乎不用。

对 450 条文本扫描注特征词（强：`曰`、`謂`；弱：`者`、`云`、`矣`、`也`），命中 4 条：

| 条目 | 特征词 | 内容 | 判定 |
| --- | --- | --- | --- |
| 03 大畜·九三 | 曰 | 良馬逐，利艱貞。**曰**：閑輿衛，利有攸往。 | **误报**：「曰」为经文原字（引语格式） |
| 05 困·上六 | 曰 | 困於葛藟，於臲卼，**曰**動悔、有悔，征吉。 | **误报**：同上 |
| 06 小過·上六 | 謂 | 弗遇過之，飛鳥離之，凶，是**謂**災眚。 | **误报**：「是謂」为经文原字 |
| 05 井·卦辞 | 也 | …汔至亦未繘井，**巳來至而未出井也**。羸其瓶，凶。 | **真阳性**：「巳來至而未出井也」是王弼注 |

**结论：450 条中注泄漏仅 05 井卦辞一处**（即已知缺陷），其余 449 条无泄漏迹象。启发式精度低（4 命中 3 误报），但召回可用——它把「原理性盲区」收敛为 1 条可裁定项。
