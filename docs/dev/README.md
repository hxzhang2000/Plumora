## 二、快速导读

1. **第一次了解项目**：按 00 → 01 → 02 → 03 的顺序阅读。00 提供「为什么这样做」的市场依据，01—03 提供产品形态与技术骨架。
2. **准备动手写代码**：重点读 02（架构与包结构）、03（算法规则是全 app 的灵魂）、04（存储契约）。
3. **做 UI**：06 是唯一依据，排盘结果页的布局约定必须严格遵守（六爻自上而下、动爻高亮）。
4. **做测试**：07 中预置了两组「金标准算例」（2026-08-15 午时 → 水风井；梅/花 → 火地晋），实现必须先通过这两组用例。

## 三、术语速查

| 术语 | 含义 |
| --- | --- |
| 本卦 | 起卦得到的原始卦象（上卦 + 下卦），代表当前状态 |
| 互卦 | 由本卦二三四爻（下卦）、三四五爻（上卦）组成，代表过程 |
| 变卦 | 本卦动爻阴阳互变后所得，代表趋势与结局 |
| 动爻 | 发生阴阳变化的爻；动爻所在之卦为「用卦」，另一卦为「体卦」 |
| 先天八卦数 | 乾1、兑2、离3、震4、巽5、坎6、艮7、坤8 |
| 体用生克 | 断卦核心原则：用生体吉、体克用吉、比和吉；体生用小凶、用克体凶 |

## 四、文档版本控制约定

**每份文档独立版本控制**——本体系**不存在**「文档集统一版本」。

### 4.1 为什么取消统一版本号

文档集曾使用「文档集版本」单一版本号（v1.0 → v1.4）。实测问题：任何一份文档改动后，其余 8 份版本号并不随之变化，索引里的「文档集版本」只能二选一——要么长期滞后（本次核查发现它停在 v1.0，而实际已到 v1.4），要么被迫让全部文档集体跳号。两种做法都失真。故自 v1.5 起删除该字段，改为每份文档各自维护版本号。

### 4.2 规则

| # | 规则 |
| --- | --- |
| 1 | 每份文档头部自带「文档版本」字段，**必须与该文档末尾「变更日志」表的最高版本号一致**（不一致即为缺陷） |
| 2 | 版本号形如 `v主.次`。**主版本 +1** = 结论性变更（改算法口径、改数据契约、删改章节）；**次版本 +1** = 补充说明、修正笔误、补交叉引用 |
| 3 | 每次修改该文档，**在同一轮内**完成三件事：改正文 → 头部版本 +1 → 末尾变更日志追加一行（写明改了哪几处、原值 → 新值） |
| 4 | **未改动的文档不升版本**。本轮修订中 00、02 未改动，故仍为 v1.0 |
| 5 | §一 的「当前版本」列是各文档版本的**只读镜像**，不是权威来源；权威来源永远是各文档自己的头部字段 |
| 6 | 文档间引用必须带版本号（如「见 03 文档 v1.4 §3.4」），便于日后判断引用是否已过期 |

### 4.3 变更日志写法

每条只写「做了什么」，不写动机论述；格式统一为 `| vX.Y | 日期 | 改了什么：① …；② … |`。模板见 08 文档 §五。

### 4.4 修订后的自查

改完一轮后，用**被更正的旧值**全文检索一遍，仍出现即为漏改（本轮互卦更正就是靠这招抓出 4 处残留）：

```bash
grep -rn "旧值" docs/ --include=*.md
```

更系统的做法是跑 `.workbuddy/checks/` 下的三个脚本（改完文档后建议全跑一遍）：

| 脚本 | 作用 | 期望输出 |
| --- | --- | --- |
| `docset-selfcheck.py` | 文档集自身卫生：头部版本 vs 变更日志、旧值残留、Markdown 表格列数、交叉引用目标章节是否存在、单文件原型 HTML 与 `build/core.js` 数据是否漂移 | 22 项通过 / 0 项待处理 |
| `doc-case-check.js` | 把 03/07 文档的用例逐条对拍 `docs/ui/build/core.js`，验证「文档说的」与「实现做的」是否一致 | 32 pass / 0 fail |
| `kb-consistency.py` | 比对 05 文档 §3.2 速查表 / §3.5 词表 / `core.js` 常量三方的 64 卦数据一致性 | 无差异 |

运行方式：

```bash
python .workbuddy/checks/docset-selfcheck.py
node   .workbuddy/checks/doc-case-check.js
python .workbuddy/checks/kb-consistency.py

# 另：HTML 原型冒烟（jsdom 需显式指定 NODE_PATH，见 docs/ui/README.md）
cd docs/ui && NODE_PATH="C:/Users/hxzha/.workbuddy/binaries/node/workspace/node_modules" \
  node build/smoke.test.js
```
