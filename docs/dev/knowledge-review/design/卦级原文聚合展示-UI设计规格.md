## 一、背景与目标

### 1.1 现状（本设计启动时）

- `packages/knowledge/src/hexagrams.ts:107-109`：`guaci / lines / yongText` **恒为 `null`**，由 `packages/knowledge/test/knowledge.test.ts:148-156` 守卫断言强制。
- `apps/web/src/components/ResultPanel.vue:378-388`：本卦 tab 底部「卦辞 · 爻辞」卡是占位文案（"M1 待录入……当前以卦意关键词 + 类象作为参考"）。
- `apps/web/src/views/LearnView.vue:116`：64 卦速查同处占位。
- 09 文档 v2.0 已完成 64 卦 450 条底库（64 卦辞 + 384 爻辞 + 2 用九用六）与程序化自检，两轮人工校对未完成、**未入库**；底库口径为 zh-hans 交付层、zh-hant 权威层（09 §4.2）。

### 1.2 本设计的目标

为**每卦详情页**（未来承载于排盘结果页的本卦 tab、学习页 64 卦速查、以及后续可能的独立卦详情路由）新增一个自包含的**「卦级原文聚合」分区**，聚合展示一卦全部原文层：

| 层级 | 数据 | 覆盖 | 视觉权重 |
| --- | --- | --- | --- |
| 主层 | 卦辞 `guaci` | 64 卦 | ★★★ 最高（起卦断卦直读） |
| 主层 | 爻辞 `lines[6]` + 每爻小象 `xiaoxiang` | 64 卦 × 6 爻 | ★★★ 最高（**动爻高亮联动排盘**） |
| 主层 | 用九/用六 `yongText` | 仅 01乾、08坤（2 卦） | ★★☆ 中等（乾坤专属经文） |
| 次层 | 彖传 `tuan` | 64 卦 | ★☆☆ 低（默认折叠） |
| 次层 | 大象 `xiang_daxiang` | 64 卦 | ★☆☆ 低（默认折叠） |
| 次层 | 文言 `wenyan` | 仅 01乾、08坤 | ★☆☆ 低（默认折叠） |

### 1.3 设计目标（一句话）

> 让「读卦」像翻一本装帧克制的宣纸册页：**卦辞爻辞一摊即读，动爻一眼可辨；学术层藏进折页，一键展开、一键复制、不与主文争位。**

### 1.4 非目标

- 不做「白话翻译 / 卦名简注」——那是 05 文档 §3.3 的 M2 项，独立范围。
- 不引入网络字体、CDN、远程资产（AGENTS.md 离线承诺）。
- 不重绘卦符、不改排盘页既有布局（06 §3.2 硬性约定一字不动）。
- 不做分享功能（09 §六 L285 已列为开放决策项）。

## 二、用户与信息架构

### 2.1 目标用户

梅花易数用户群偏中老年。设计取舍优先级：

1. **可读性 > 视觉冲击**——宁可保守，不可炫技。
2. **一步即达 > 多步导航**——用户起完卦，想读的是「这一卦怎么断」，不想再点三层。
3. **动爻联动 > 完整聚合**——动爻爻辞是本卦断卦的核心文本，视觉权重永远最高。
4. **学术层默认收起 > 一次性铺开**——彖/象/文言是"查得到"即可，日常断卦不读。

### 2.2 分区在页面中的位置

本设计将「卦级原文聚合」视为一个**可嵌入的自包含分区组件**（下文称为 `<TextAggregate>`，仅命名，不涉实现）。落地时的三种可能宿主：

| 宿主 | 位置 | 说明 |
| --- | --- | --- |
| `ResultPanel.vue` 本卦 tab | 结论卡 + 类象卡之后，替换现占位卡 | 起卦断卦直读，动爻高亮联动当前排盘 |
| `LearnView.vue` 64 卦速查详情 | 点格进入的独立路由/弹窗 | 无动爻，全六爻平等展示；无排盘联动 |
| 未来独立卦详情路由 | `/hexagram/:code` | 独立阅读页，可选 |

> ⚠️ **动爻来源差异**：本设计把「动爻」建模为 `<TextAggregate>` 的一个**可选输入**（`moving?: number`）。在排盘结果页由起卦上下文给出；在学习页/独立路由则缺省，六爻一律按非动爻样式呈现。这与 06 §3.2 的动爻语义一致（动爻仅在本卦有）。

### 2.3 分区内部的信息层级

```
┌─────────────────────────────────────────┐
│  卦辞 · 爻辞 · 用九/用六                 │  ← 主区，永远展开
│  ─────────────────────────              │
│  卦辞卡        [⧉ 复制]                 │
│  爻辞卡组      [每爻独立展开态]          │
│  用九/用六卡   [仅乾坤出现]              │
├─────────────────────────────────────────┤
│  ▸ 彖 · 象 · 文言（学术层）             │  ← 次区，默认折叠
│    （点按展开；展开后内含：彖传卡 /      │
│      大象卡 / 文言卡[仅乾坤]）           │
└─────────────────────────────────────────┘
```

## 三、数据字段依赖（对拍当前 schema）

### 3.1 需要 vs 现有

以 `packages/knowledge/src/hexagrams.ts` 的 `Hexagram` interface 为基准逐字段对拍：

| UI 需要字段 | 现有 schema | 状态 | 备注 |
| --- | --- | --- | --- |
| 卦辞正文 | `guaci: string \| null` | ✅ **已有** | 含「XX：」前缀（09 §六 L288 口径），展示时**保留前缀**——「乾：元、亨、利、贞。」是原文完整形态 |
| 爻辞正文 | `lines[i].text` | ✅ **已有** | 不含爻名（09 §六 L288 口径），UI 由 `lines[i].name` 补名 |
| 爻名 | `lines[i].name` | ✅ **已有** | 「初九」/「九二」/「上六」等；含"初"/"上"前缀 |
| 爻位序号 | `lines[i].index` | ✅ **已有** | 1–6，1 = 初爻 |
| 用九/用六 | `yongText: string \| null` | ✅ **已有** | 仅乾坤非 null |
| 小象（每条爻） | ❌ **缺失** | ⚠️ 需新增 | 建议加入 `HexagramLine.xiaoxiang: string \| null`（"潛龍勿用，陽在下也。"） |
| 彖传 | ❌ **缺失** | ⚠️ 需新增 | 建议新增 `tuan: string \| null`（每卦 1 段） |
| 大象 | ❌ **缺失** | ⚠️ 需新增 | 建议新增 `xiang_daxiang: string \| null`（每卦 1 段，如"天行健，君子以自強不息。"） |
| 文言 | ❌ **缺失** | ⚠️ 需新增 | 建议新增 `wenyan: string \| null` 或 `wenyan: readonly string[] \| null`（仅乾坤） |

### 3.2 数据量测算（每卦一条聚合后）

| 卦类别 | 段落数 | 说明 |
| --- | --- | --- |
| 乾坤（2 卦） | 卦辞 1 + 爻辞 6 + 小象 6 + 用九/用六 1 + 彖 1 + 大象 1 + 文言 1~6 段 ≈ **17–22 段** | 最长的一卦 |
| 其余 62 卦 | 卦辞 1 + 爻辞 6 + 小象 6 + 彖 1 + 大象 1 = **15 段** | 常规 |

单页文字最长量级：15–22 段 × 平均 40 字 ≈ **600–900 字**。**这是"一屏装不下、一页装得下"的量级**——决定了推荐方案必须能"折叠"而非"全铺开"。

### 3.3 依赖与 09 文档口径的冲突（**需 orchestrator 决策，见 §十 Q1**）

09 文档 v2.0 §一 L29 明确把「彖传 / 象传 / 文言」列为**非目标**（"05 §3.3 M3，可选"），本轮只产出 450 条底库（卦辞+爻辞+用九用六）。**这意味着：**

- **本设计的"次层"（彖/象/文言）在数据入库时可能仍为 `null`**；
- 本设计因此**必须**具备"字段缺失 → 不占空槽、不显占位"的降级路径（见 §5.4）；
- 建议 orchestrator 在决策中明确：本轮 UI 是否等 09 文档扩范围后再落地次层？还是次层先做**占位预留**（数据一到即显）？

## 四、三个视觉方案对比

### 方案 A：纵向长卷（Scroll of Classical Text）

**隐喻**：传统手卷/长卷——从卦辞一路读到文言，一气呵成。

```
┌──────────────────────────┐
│ 卦辞                     │
│ 「水風井：改邑不改井…」  │
├──────────────────────────┤
│ 初六                     │
│ 「井泥不食，舊井無禽。」  │
│ ─ 小象：井泥不食，下也    │
├──────────────────────────┤
│ 九二                     │
│ 「井谷射鮒，醜悔，亡。」  │
│ ─ 小象：井谷射鮒，徃為上  │
├──────────────────────────┤
│ ⋮                       │
├──────────────────────────┤
│ 象                       │
│ 「木上有水，井。君子以    │
│ 勞民勸相，甘之食。」      │
├──────────────────────────┤
│ 彖                       │
│ 「井，井也。改邑不改井…」 │
└──────────────────────────┘
```

| 项 | 说明 |
| --- | --- |
| 优点 | 阅读节奏连续，无折叠打断；符合"逐段诵读"的中式阅读习惯；实现最简单（顺序铺开即可） |
| 缺点 | 主层与次层视觉权重趋同；乾坤一卦 22 段，滚到文言前必须先翻过 6 段学术前的所有内容；**主用文本（卦辞爻辞）与学术参考层抢注意力**；用户想复制单段需先找到位置再长按选词，操作成本高 |
| 场景匹配 | 更像"阅读模式"，不适合"断卦直查" |
| 建议 | ❌ **不推荐**——与"卦辞爻辞最高权重、学术层默认收起"的设计目标冲突 |

---

### 方案 B：分段卡片（Segmented Cards）

**隐喻**：一叠竖立册页——每种原文一类，各成一张卡片，卡片间用宣纸底色留白分隔。

```
┌──────────────────────────┐
│ 【卦辞】        ⧉ 复制   │
│ 「水風井：改邑不改井…」  │
└──────────────────────────┘
        
┌──────────────────────────┐
│ 【爻辞】                 │
│ ─────────────────        │
│ 初六 井泥不食…   ⧉      │
│ 九二 井谷射鮒…   ⧉      │
│ 九三 井冽寒泉…   ⧉      │
│ 六四 井甃无咎…   ⧉      │
│ 九五 井洌寒泉…   ⧉      │
│ 上六 井收勿幕…   ⧉      │
│ （每爻小象默认隐藏，点击爻名展开） │
└──────────────────────────┘

┌──────────────────────────┐
│ 【彖 · 象】              │
│ ─────────────────        │
│ 彖：井，井也。改邑不改井…│
│ 象：木上有水，井…        │
└──────────────────────────┘
```

| 项 | 说明 |
| --- | --- |
| 优点 | 层级清晰（每类原文一卡）；每卡独立可复制；卡片数量固定，认知成本低；卡片可独立折叠，不影响其他卡 |
| 缺点 | 卡片过多（乾坤一卦 4 张 + 主卡内 6 条爻辞行 = 视觉单元太多）；主层与次层视觉上"平级"（除非加视觉装饰区分）；爻辞卡内部还需处理"小象展开" |
| 场景匹配 | 折中——比方案 A 好，但仍不足以拉开主层/次层权重差 |
| 建议 | ⚠️ **部分采用**——分段卡片的思路可保留，但主/次层需通过默认折叠状态拉开权重 |

---

### 方案 C：分层 Tab（Layered Tabs）

**隐喻**：一本翻开的书——主层是"卦经"，次层是"传注"，两个 tab 切换。

```
┌──────────────────────────┐
│ [ 卦经 ] [ 传注 ]         │  ← 分层 Tab
├──────────────────────────┤
│                          │
│  【卦辞】                │
│  「水風井…」            │
│                          │
│  【爻辞】                │
│  初六 · 九二 · 九三 …   │
│                          │
│  【用九/用六】(仅乾坤)   │
├──────────────────────────┤
│                          │
│  （切到"传注"tab 后：）  │
│  【彖】                  │
│  【象】                  │
│  【文言】(仅乾坤)        │
└──────────────────────────┘
```

| 项 | 说明 |
| --- | --- |
| 优点 | 主/次层权重差最强（一个 tab 永远可见，另一个 tab 隐藏）；一次只显示一层，界面克制 |
| 缺点 | 结果页已有「本卦/互卦/变卦」三块切换器（06 §3.2），再来一组 tab 会造成"tab 疲劳"；用户起完卦想直读卦辞爻辞，多一层 tab 就多一步；次层可发现性弱（新用户可能不知道还有「传注」tab） |
| 场景匹配 | 独立卦详情路由场景下合适；嵌入排盘结果页则**冗余** |
| 建议 | ❌ **不推荐**（嵌入场景）——已有三层导航，避免叠加 |

---

### 方案 D（推荐）：主区直开 + 次区手风琴折叠

**综合方案 B 的卡片思路 + 方案 A 的连续阅读感，用"默认折叠状态"拉开主/次层权重。**

```
┌────────────────────────────────────┐
│ 卦辞 · 爻辞 · 用九（或"卦辞 · 爻辞"）│  ← 主区永远展开
│ ═══════════════════════════════   │
│                                    │
│ 卦辞         ⧉                    │
│ 「水風井：改邑不改井…羸其瓶，凶。」│
│                                    │
│ 爻辞                                │
│ ┌──初六 ●──┐ 井泥不食，舊井無禽。 ⧉ │  ← ● 是动爻（若本卦有动爻）
│ │ 点击展开 │ （下：井泥不食，下也） │     小象默认随爻辞展开显示
│ └─────────┘                        │
│ ┌──九二──┐ 井谷射鮒，醜悔，亡。 ⧉ │
│ ┌──九三──┐ 井冽寒泉，食。       ⧉ │
│ ┌──六四──┐ 井甃，無咎。         ⧉ │
│ ┌──九五──┐ 井洌，寒泉食。       ⧉ │
│ ┌──上六──┐ 井收，勿幕有孚，元吉。⧉ │
│                                    │
│ （乾坤专属）用九         ⧉         │
│ 「見群龍無首，吉。」              │
├────────────────────────────────────┤
│  ▸ 彖 · 象 · 文言（学术层，点按展开）│  ← 次区默认折叠
│                                    │
│  （展开后：）                       │
│  彖  ⧉                            │
│  「井，井也。改邑不改井，无喪無得…」│
│                                    │
│  大象  ⧉                          │
│  「木上有水，井。君子以勞民勸相…」 │
│                                    │
│  （乾坤专属）文言  ⧉               │
│  「初九曰：潛龍勿用，下也。        │
│    見龍在田，德均也。…」           │
└────────────────────────────────────┘
```

| 项 | 说明 |
| --- | --- |
| 优点 | ✅ 主/次层权重差**用默认折叠状态**实现，不引入新 tab 层级；主区永远可见，符合"起完卦即读"的心智模型；次区"一键展开"、可发现性靠标题字重+箭头提示 |
| 优点 | ✅ 单卡「复制」按钮覆盖所有段（卦辞、每条爻辞、小象、彖、象、文言） |
| 优点 | ✅ 动爻高亮直接内联在爻辞卡（朱砂圆点 + 底色），与排盘上爻圆点视觉语义完全一致 |
| 优点 | ✅ 主区内容少（卦辞 1 + 爻辞 6 + 用九 1 = 最多 8 段），次区"要读才读"——单页高度可控 |
| 缺点 | 折叠动画实现稍复杂；次区展开后的位置会推挤下方（若嵌入排盘页，下方内容会被顶下）——但本功能在排盘页是**末位分区**，无下方内容，此缺点可忽略 |
| 场景匹配 | ✅ 同时适配排盘结果页嵌入、学习页详情、独立路由 |
| 建议 | ✅ **推荐采用** |

### 方案取舍小结

| 维度 | A 纵向长卷 | B 分段卡片 | C 分层 Tab | **D 主直开+次折叠** |
| --- | --- | --- | --- | --- |

| 与已有「本/互/变」tab 冲突 | ❌ 无 | ❌ 无 | ⚠️ 叠加 | ❌ 无 |
| 单页视觉单元数（乾坤最坏） | 22 | 4 卡+6 行 | 2 tab | 主 8 + 次折叠 1 |
| 复制操作便利度 | ⚠️ 长按选词 | ✅ 每卡 ⧉ | ✅ 每卡 ⧉ | ✅ 每段 ⧉ |
| 实现复杂度 | ★ | ★★ | ★★★ | ★★★ |
| **推荐度** | ❌ | ⚠️ | ❌ | **✅** |

## 五、推荐方案（方案 D）详细设计

### 5.1 结构分层

分区由两层构成：

1. **主区（永远展开）**：
   - 分区总标题（含本卦名，供用户确认"读的是哪一卦"）
   - 卦辞卡（`guaci` 非 null 时显示）
   - 爻辞卡（`lines` 非 null 时显示，含 6 条爻辞 + 小象 + 动爻高亮）
   - 用九/用六卡（`yongText` 非 null 时显示，乾坤专属）

2. **次区（默认折叠的手风琴）**：
   - 折叠触发器（一条可点击的标题条，右侧指示箭头）
   - 展开后依次显示：
     - 彖传卡（`tuan` 非 null 时显示）
     - 大象卡（`xiang_daxiang` 非 null 时显示）
     - 文言卡（`wenyan` 非 null 时显示，乾坤专属）

### 5.2 主区详细布局

#### 分区总标题

- 结构：`卦辞 · 爻辞 · 用九`（乾坤）/ `卦辞 · 爻辞`（其他卦）
- 位置：分区顶部，左对齐
- 字号：`var(--fs-sm)`（12.5px），字重 500
- 颜色：`var(--c-muted)`
- 字间距：`letter-spacing: 2px`（与 06 §3.2 `.p-cap` 一致的"章节眉"风格）
- 装饰：**左侧一条 4px 长的朱砂横线**（`border-left: 3px solid var(--c-accent); padding-left: 10px;`），呼应结果页 `.p-cap` 的视觉语言
- 复制按钮：主区标题右侧不放总复制；分卡各自复制

#### 卦辞卡

- 结构：单行卡片
- 布局：标题"卦辞"左对齐，右上 ⧉ 复制按钮；下方是卦辞正文
- 字体：**宋体**（`var(--font-serif)`）——这是本设计唯一主动选宋体的场景，理由：
  - 06 §4.2 已定义 `--font-serif`（Noto Serif SC / Songti SC / SimSun）
  - 卦辞爻辞是**古典原文**，宋体在视觉气质上契合"古典原文"的语义定位
  - 与排盘页卦名的 `.serif` 类保持一致，让"卦名"与"卦辞"形成同一视觉系统
- 字号：`clamp(15px, 4.4vw, 17px)`（`var(--fs-md)` 到 `var(--fs-lg)`）——老年用户友好
- 行高：`1.85`（比正文 1.7 更宽松，为古典文本留气口）
- 字距：`letter-spacing: 0.5px`
- 颜色：`var(--c-text)`
- 段落间距：段落内不断段（卦辞是一整段，如「乾：元、亨、利、贞。」），句末全角句号保留
- 卡片底：`var(--c-surface)`，`border: 1px solid var(--c-line)`，`border-radius: var(--r-lg)`，`box-shadow: var(--shadow-card)`——与结果页 `.card` 一致
- 内边距：`padding: 16px 18px`（`var(--sp-4) var(--sp-5)`）

#### 爻辞卡组

爻辞卡不是 6 张独立卡，而是**一张卡内含 6 条爻辞行**。这样减少视觉单元、便于用户"从上到下顺读六爻"。

- 卡片结构：标题"爻辞"，右上不额外置按钮（每行自带 ⧉）
- 每条爻辞行结构（自上而下）：
  1. **行头**：左：爻名徽标 + （可选）朱砂圆点；右：⧉ 复制按钮
  2. **正文**：爻辞全文（宋体，同卦辞卡字号）
  3. **小象行**（默认隐藏；点按爻名徽标展开；展开后是次级宋体小字）
- 动爻高亮：
  - **行头圆点**：朱砂实心圆点（`background: var(--c-accent)`），直径 10px，与排盘上爻右侧圆点视觉语义完全一致（06 §3.2）
  - **整行底色**：`background: var(--c-accent-soft)`（`rgba(176, 58, 46, 0.08)`，已在 tokens.css 定义），左内边框 `border-left: 3px solid var(--c-accent)`——**双重信号**：圆点标示"哪爻动"、底色标示"这一行是动爻爻辞"
- 非动爻行：无圆点、无底色、无左边框；行与行之间由 1px 虚线分隔（`border-bottom: 1px dashed var(--c-line)`）
- 分隔：虚线延伸到 ⧉ 按钮左侧，让按钮"浮"在行尾

- **爻名徽标**（点击后展开小象）：
  - 视觉：`background: var(--c-surface-2)`，`color: var(--c-ink)`，`padding: 2px 10px`，`border-radius: var(--r-pill)`
  - 字号：`var(--fs-sm)`（12.5px），字重 500，字间距 `letter-spacing: 0.5px`
  - 动爻徽标额外样式：`background: var(--c-accent-soft)`，`color: var(--c-accent)`，字重 600
  - 光标：`cursor: pointer`；`:hover` 时描边 `border-color: var(--c-accent)`（提示可点）
  - 无障碍：`role="button"`，`aria-expanded`，`aria-controls` 指向小象行
  - **交互**：点按爻名徽标 → 展开该爻的小象文本（`xiaoxiang`）；再点一次 → 收起。默认所有小象行**收起**（避免一次展开太多）。

- **一键展开所有小象**：卡右上角加一个次级按钮「展开小象」/「收起小象」（`var(--fs-xs)`，`color: var(--c-muted)`，无按钮框），点击后所有爻名徽标同时展开/收起。**避免用户点 6 次**。

- **小象文本样式**：
  - 字号：`var(--fs-sm)`（12.5px）
  - 字重：400
  - 颜色：`var(--c-muted)`
  - 字体：**宋体**（与爻辞同族，视觉上一体感）
  - 行高：`1.7`
  - 内嵌位置：爻辞正文之下、下一分隔线之上
  - 视觉区分：左侧 `padding-left: 26px`（与爻名徽标对齐）+ 顶部一条 `border-top: 1px dotted var(--c-line)` 虚线连接符
  - **前缀**：`《小象》`（灰色小号字体 `var(--fs-xs)`，`color: var(--c-muted)`，`margin-right: 6px`）——**为什么加前缀**：小象是"某爻之象"，与爻辞并列时若无前缀会被误读为爻辞续句。前缀让语义明确。

#### 用九/用六卡（乾坤专属）

- 仅当 `yongText !== null` 时出现（乾坤）
- 视觉位置：爻辞卡**之下**（用九是"六爻之外"的补充经文，故放在爻辞之后）
- 卡片样式：与卦辞卡同款，但**右上加一枚徽标**标注经文名——
  - 乾（`code === '01-01'`）：徽标文字 `用九`
  - 坤（`code === '08-08'`）：徽标文字 `用六`
- 徽标视觉：`background: var(--c-accent-soft)`，`color: var(--c-accent)`，`padding: 2px 10px`，`border-radius: var(--r-pill)`，`font-size: var(--fs-xs)`，`letter-spacing: 1px`
- 正文：`yongText` 全文（如「見群龍無首，吉。」），宋体、同卦辞字号

### 5.4 降级路径（数据缺失时的显示）

由于 09 文档当前只录入卦辞+爻辞+用九（450 条），彖/象/文言及小象在本轮入库时可能为 `null`。**UI 必须对每个字段独立降级**：

| 字段 | 状态 | UI 显示 |
| --- | --- | --- |
| `guaci` | `null` | **整卡隐藏**（不显占位，不显"M1 待录入"）——避免占位文本重复出现（现 ResultPanel 已有占位卡，本设计不应加第二处占位） |
| `lines` | `null` | 爻辞卡整卡隐藏 |
| `lines[i].xiaoxiang` | `null` | 该爻展开态不显示小象行；**爻名徽标不显示"可展开"光标**（改为不可点样式），避免"点了没反应"的空交互 |
| `yongText` | `null` | 用九/用六卡整卡隐藏 |
| `tuan` | `null` | 彖卡整卡隐藏 |
| `xiang_daxiang` | `null` | 大象卡整卡隐藏 |
| `wenyan` | `null` | 文言卡整卡隐藏 |
| 次区所有内容都为 `null` | | **整条折叠触发器不显示**（连标题都不出现） |

**空态判断规则**：
- 主区**至少**显示 1 张卡（卦辞 或 爻辞 或 用九，三选一）——否则整个 `<TextAggregate>` 分区不渲染
- 主区所有卡片都为 `null` 时（极端情况，数据异常）：显示一行空态提示「原文待录入」（`var(--fs-sm)`，`var(--c-muted)`，居中），并附一条 `title` 属性提示用户"数据校对完成后自动显示"

### 5.5 交互与动画

#### 一键复制

- 每段右上角 ⧉ 图标（16px 描边 SVG，`stroke: currentColor`）
- 图标色：`var(--c-muted)`，`opacity: 0.6`
- 点击：
  - 图标变为 ✓（对勾）
  - 图标色变为 `var(--c-accent)`（朱砂）
  - **同时**触发全局 toast「已复制」（复用现有 `apps/web/src/stores/toast.ts`）
- 恢复：2.5 秒后图标回到 ⧉
- 剪贴板内容：
  - 卦辞：完整 `guaci` 字符串（含「XX：」前缀）
  - 爻辞：`{name}　{text}`（爻名 + 全角空格 + 爻辞，**不含小象**）
  - 小象：`《小象》　{xiaoxiang}`
  - 用九/用六：`{kind}　{text}`（如「用九　見群龍無首，吉。」）
  - 彖 / 象 / 文言：直接文本
- 复制失败降级：toast「复制失败，请长按选择文本」（浏览器剪贴板 API 拒绝时的兜底）
- 无障碍：图标按钮有 `aria-label="复制卦辞"`（或对应内容名）；`aria-pressed` 或瞬时的 `aria-live` 提示

#### 爻名点击跳排盘位置（**跨组件联动**）

- 只在**排盘结果页嵌入**时启用；学习页/独立路由无排盘、不启用
- 交互：点击爻辞卡中的爻名徽标 → 排盘上方 `.glyph`（`HexagramGlyph`）中对应爻**闪烁一次朱砂脉冲**（不是滚动，因为通常排盘就在文本卡上方，用户已能看到）
- 实现方式（设计建议，具体由开发实现）：
  - `<TextAggregate>` 通过 `emits` 抛出 `select-line` 事件（载荷：爻位 1–6）
  - 父组件 `ResultPanel` 监听并调用排盘卦符的 `scrollIntoView` / 触发高亮类
  - 高亮动画：目标爻行 `.yao` 添加 `class="ping"`，CSS keyframes 一次 `scale + shadow` 脉冲（0.6s），`prefers-reduced-motion` 时降级为一次性边框变色
- **为什么不是"跳到"**：排盘与原文卡在同页，用户视觉上不需要滚动"跳"；但需要一个明确信号让用户确认"我看的是哪一爻"——**脉冲**是最低干扰的信号形式
- 动爻行点击 → 触发脉冲后，脉冲点即排盘上的朱砂圆点位置，形成"文本 ↔ 图形"闭环

#### 手风琴折叠动画

- 展开：`grid-template-rows: 0fr → 1fr` 的 CSS 过渡（现代主流手风琴实现，兼容性好）；配合 `opacity: 0 → 1`
- 收起：反向
- 时长：`0.24s`（比 `--dur: 0.22s` 略长，让"打开折页"的动作有仪式感但不拖沓）
- 缓动：`var(--ease)`（cubic-bezier(0.2, 0.8, 0.3, 1)）——沿用 tokens.css
- `prefers-reduced-motion`：动画时长设为 0，直接切换显示态

#### 一键展开所有小象

- 按钮文案：`展开小象` → 点击后 → `收起小象`
- 每个小象行的展开/收起与手风琴同款动画
- 若某爻 `xiaoxiang = null`，该行不参与"全部展开"，且该爻行仍保持不可点

#### 主区"卦辞·爻辞"分区标题滚动吸附（可选）

- 当用户滚动浏览爻辞卡时，分区标题可 `position: sticky; top: 0` 吸附在页顶——但排盘页 tab 组也在页顶，二者冲突。**故不启用吸附**，只在独立卦详情路由（若未来建立）中启用。

### 5.6 无障碍（对拍 06 §6.1）

| 项 | 要求 | 建议实现 |
| --- | --- | --- |
| 屏幕阅读器 | 分区可朗读，动爻信息传达 | 分区根 `role="region"`，`aria-labelledby` 指向分区总标题；动爻行 `<article aria-label="初爻动，爻辞：井泥不食，舊井無禽。">` |
| 键盘导航 | 手风琴、复制按钮、爻名徽标均可键盘操作 | 所有交互元素使用原生 `<button>` 或 `role="button"` + `tabindex`；方向键上下在爻辞行之间移动；Enter / Space 触发 |
| 焦点可见性 | 复制按钮、手风琴触发器、爻名徽标聚焦时有明确焦点环 | `:focus-visible { outline: 2px solid var(--c-accent); outline-offset: 2px; }`——用朱砂色焦点，与"强调"色一致 |
| 对比度 | WCAG AA 4.5:1 正文，3:1 大字 | 主文字 `var(--c-text) #2B2B2B` 于 `var(--c-surface) #FFFFFF` 上对比度 ≈ 14.8:1（远高于 AA）；小象 `var(--c-muted) #8A8578` 于白底对比度 ≈ 4.0:1，**接近 AA 边界**——因此小象字号必须 ≥ 12.5px 且字重不轻于 400；深色主题下对比度重新测算 |
| 触控目标 | 最小 48×48 | ⧉ 按钮 32×32 图标 + `padding: 8px` 使可点区达 48×48；爻名徽标高 24px，加 `padding-block: 8px` 达 40px（仍不足 48）——**改进**：爻名徽标 `min-height: 32px` + `padding: 0 10px`，配合外边距 `margin: 8px 0`，热区有效触达 48px |
| 字体缩放 | 支持 1.0–1.3 系统缩放不破版 | 所有字号用 `rem` 而非 `px`（tokens.css 已是 `px`——**建议**：在分区 CSS 中把 `--fs-*` 换算为 rem 覆盖；或至少在本文档中标注，由实装阶段决定是否升级令牌） |
| 动效降级 | `prefers-reduced-motion` 时减少动画 | 折叠动画、脉冲动画均检测该媒体查询，降级为无动画切换 |

### 5.7 响应式断点建议

沿用 06 §6.2 的两大断点（< 900px 移动 / ≥ 900px 桌面），本分区不引入新断点。

#### 手机竖屏（< 360px）

- 内容区全宽，`padding: 16px`
- 卦辞、爻辞卡内边距 `14px 16px`
- 字号 `clamp(15px, 4.4vw, 17px)` 会 clamp 到约 15px
- 动爻圆点 8px（缩一档）
- 手风琴触发器高度 44px（略低于 48，但触控仍可达）

#### 手机竖屏标准（360–480px，主流 iPhone / Android）

- 字号 clamp 中间值 ≈ 16px
- 卦辞/爻辞卡片内边距 16px 18px
- 爻名徽标 24px 高
- 复制按钮 32×32 热区 48×48

#### 手机横屏 / 平板竖屏（480–900px）

- 内容区居中，`max-width: 720px`（比 06 `--content-max: 1080px` 窄，因为单栏文本 720px 已足够易读；不铺满）
- 字号 clamp 上限 17px
- 卡内边距 `20px 24px`（放宽呼吸感）

#### 平板横屏 / 桌面（≥ 900px）

- 内容区居中，`max-width: 780px`（单栏文本在 1080px 上限内，但**再收窄**到 780px 保证行长 20–32 字，符合"古典文本易读"经验值）
- 卦辞、爻辞字号上限 `var(--fs-lg)` = 17px
- 手风琴与卡片间距 20px（`var(--sp-5)`）
- 桌面端可考虑 `column-count: 1` 保持单栏——**不启用双栏**：双栏会打断"从上到下顺读"的语义

## 六、动效建议（克制不喧宾夺主）

06 §五 的动效原则是「安静的水墨气质」，动效服务于内容而非内容服务于动效。本分区动效清单：

| 场景 | 动效 | 时长 | 备注 |
| --- | --- | --- | --- |
| 分区首次加载 | 无（直接渲染） | — | 排盘页已有"逐爻浮现"动画，本页不叠加 |
| 手风琴展开 | `grid-template-rows` 0→1fr + `opacity` 0→1 | 240ms | 缓动 `var(--ease)` |
| 手风琴收起 | 反向 | 240ms | 同上 |
| 小象行展开（点击单个爻名） | 同上但略快 | 200ms | 与主手风琴区分层次 |
| 小象行展开（"展开所有小象"） | 依次 stagger 20ms | 6 × 200ms = 1.2s 总长 | **仅首次展开** stagger，收起时不 stagger（一次性收） |
| 复制按钮 | 图标 SVG 从 ⧉ morph 到 ✓（`stroke-dashoffset` 或 CSS `clip-path`） | 200ms | 恢复 2.5s 后 |
| 复制按钮 hover | `opacity: 0.6 → 1`，`color` 向 `var(--c-accent)` 过渡 | 150ms | — |
| 爻名徽标 hover | 边框描边颜色向 `var(--c-accent)` 过渡 | 150ms | 提示可点 |
| 动爻行入场（分区首次加载） | 底色淡入 `opacity: 0 → 1`，圆点弹入 `scale(0) → scale(1)` 0.4s 延迟 0.3s 后触发 | 400ms | 让动爻视觉信号**晚于**其他爻出现——模仿排盘页"动爻圆点最后弹入"的既有节奏（06 §五 L212） |
| 爻名点击脉冲排盘对应爻 | 目标爻行 `box-shadow` 朱砂脉冲 0.6s | 600ms | 一次性，不循环 |
| `prefers-reduced-motion` | 全部降级为瞬时切换 | 0ms | 06 §六 已定义全局降级策略 |

**避免**：
- ❌ 手风琴箭头旋转超过 90°（视觉混乱）
- ❌ 分区整体入场动画（与排盘动画冲突）
- ❌ 卡片 hover 上浮（结果页 tab 已有上浮，本页作为"内容型"分区不应喧宾）
- ❌ 复制成功时的粒子/彩带（违和，与"安静水墨"基调冲突）

## 附录 A：动效实现要点（供实现阶段参考）

- **折叠动画**：现代 CSS 手风琴标准做法是 `display: grid; grid-template-rows: 0fr; transition: grid-template-rows 0.24s var(--ease);` 展开时切到 `1fr`——比 `max-height` 兼容性好、能自动适应内容高度
- **图标 morph**：SVG 的 `stroke-dashoffset` 可实现"线条被笔画出来"的效果；复制成功从 ⧉ 到 ✓ 可拆为两个 SVG 分别 fade/scale
- **动爻脉冲**：CSS keyframes `@keyframes pulse { 0% { box-shadow: 0 0 0 0 rgba(176,58,46,0.4); } 100% { box-shadow: 0 0 0 12px rgba(176,58,46,0); } }`
- **无障碍动画降级**：全部动画用 `@media (prefers-reduced-motion: reduce) { animation-duration: 0.01ms !important; transition-duration: 0.01ms !important; }` 兜底（tokens.css 已在全局启用）

## 附录 B：与 06 §4.2 字体规范的一致性说明

- 06 §4.2 定义"卦名 / 标题 → 思源宋体（Noto Serif SC）"、"正文 → 系统默认"
- 本设计将卦辞、爻辞、小象、彖、象、文言的**正文文本**统一使用 `var(--font-serif)`（宋体），理由：
  - 这些文本是**古典原文**，与"标题"处于同一"原文层"，视觉气质应一致
  - 06 §4.2 未明确禁止正文使用宋体，仅在语义上给"标题"用
  - 宋体在中文排版上更适合长文阅读（字宽整齐、有古典感）
  - 老年用户群体对宋体辨识度高（与书籍、报纸同源）
- **潜在风险**：Noto Serif SC 若未在用户系统安装，会降级到 `Songti SC` / `SimSun` / `STSong` / `serif`——宋体家族在所有平台都可用，风险低
- **若 orchestrator 判定这与 06 §4.2 冲突**：可回退为系统默认无衬线字体，代价是失去"古典原文"的视觉气质，但功能不受影响
